# Meta-repo for the UP-Term source tree

Decision (2026-10-06, owner asked "should the repos be merged?"): do not merge.
Pin the repos together in one small meta-repo, give it a bootstrap script, record
the parts' commits in the kit, and make the programs name what is missing.

## Why not merge (facts, inventory run 2026-10-06)

- The coupling is build-time only. A user installs `build/UP-Term.lha` (prebuilt
  binaries); only a developer needs the repos.
- The repos differ in kind: ixemul-vtcon is a fork of ixemul 48.2 (GPL +
  LGPL, upstream history); amiga-gcc and amiga-gcc15 are bebbo's toolchain trees
  (GPLv2); upterm-ports holds recipes and patches for GPL programs; vtcon,
  neovim-amiga, tmux-amiga, cpython-amiga are ports and our own code. One
  history would mix licences and make upstream merges harder.
- Cross references today (grep of Makefile, *.mk, *.sh, *.py, RULES.md; counts per
  repo: vtcon 21, ixemul-vtcon 4, upterm-ports 5, neovim-amiga 5, cpython-amiga
  5): all `$(HOME)/Code/<repo>` defaults with `?=` overrides, except
  `tools/rig/ixpty_rig.py:18`, `tools/rig/tmux_rig.py:26`,
  `tools/rig/rig.py:39` (a Kickstart ROM under `Up_Rough_Demo_System`),
  `tools/rig/tablat.py:3`, ixemul-vtcon `tools/vector-audit.py:14`, and
  `/opt/homebrew/opt/vbcc` at `Makefile:520,660,676` and
  `tools/vbcc-aos68k.cfg`.

## Problems the plan must fix (all measured)

1. `screen-amiga` is not a git repository: it cannot be cloned or pinned.
2. Six of the eight own repos have no README first line saying what they are
   (upterm-ports, neovim-amiga, tmux-amiga, cpython-amiga; screen-amiga likewise).
   Owner rule (2026-10-06): no licence files for our own code ("no licences when not
   needed"). dctelnet-vtcon's `LICENSE` stays, reduced to its title plus the line that
   DCTelnet has no licence file and the owner states it is free and open source.
   `dist/` has no top-level file naming the shipped third-party parts and where
   their source is (only the vendored coreutils COPYING).
3. `amiga-gcc` (gcc 6.5, installs to `~/opt/amiga`) and `amiga-gcc15` (gcc 16,
   installs to `~/opt/amiga16`) are both dirty (`Makefile`, `default-repos`
   modified): the toolchain cannot be rebuilt from git state. ixemul-vtcon's
   own build also needs `~/opt/amiga` for NDK headers and `libamiga.a`.
4. The kit records no versions or commits of its parts (grep of `Makefile`, `dist/`).
5. `upterm-ports` is not consumed by `make dist`: the kit ships coreutils from
   `dist/gg/coreutils-5.2.1` (vendored in vtcon); ports `kit-stage` writes
   `build/kit/userland`, and its comment ("vtcon item 1.10 consumes it") is not wired.
6. dctelnet-vtcon builds against its own vendored copy at
   `src/third_party/vtcon`; whether it matches vtcon main is unknown.
7. The NDK 3.2R4 headers must be unpacked by hand into
   `vendor/ndk-3.2r4-Include_H` (gitignored); a missing NDK fails deep in a compile.
8. `make dist` consumes: ixemul.library and ixnet.library (ixemul-vtcon
   `build295`), the screen binary (`screen-amiga/src/screen`), the tmux binary
   (`tmux-amiga/build/tmux-bin`), `cpython-amiga/build/m68k/dist/Python3`,
   `neovim-amiga/build/v012/dist/nvim` (`Makefile:207,209,382,682-687`). It fails
   with a bare make error when any is missing.

## Decisions (made; the owner can veto)

- **Layout:** the workspace root is the parent directory of the meta-repo
  checkout, so today's `~/Code/<repo>` layout stays valid and nothing moves.
  Every script reads `UPTERM_ROOT` (default: that parent directory).
- **Pinning:** a plain `repos.lock` file plus a script, not git submodules.
  Submodules fight feature branches (ixemul-vtcon is on `feature/ixemul-80`) and
  dirty trees; a lock file records `name url branch commit` per line.
- **Name:** the meta-repo is `upterm` (GitHub `spotUP/upterm`). It holds no source of the
  parts, only: `repos.lock`, `bin/upterm-bootstrap`, `bin/upterm-doctor`,
  `toolchain/` (patches and pinned commits), `README.md`, `LICENSES.md`.
- **Toolchains:** `toolchain/` pins bebbo's commits for both gcc trees and carries
  our local modifications as patch files, so `~/opt/amiga` and `~/opt/amiga16`
  rebuild from git state. The 2.95.3 compiler stays in the `ixemul-gcc295` docker image.
- **Errors:** local, actionable messages at the boundaries; no telemetry.

## Phase 1: Make every part a pinnable git repo with a licence

Files and actions:
- `git init` in `~/Code/screen-amiga`, commit `src/Makefile.amiga` and the patches;
  keep the 4.0.3 and 4.9.1 tarballs out of git (a `fetch` script with their
  sha256, the way `upterm-ports` fetches sources); push to `spotUP/screen-amiga`.
- Commit the local changes in `amiga-gcc` (`Makefile`) and `amiga-gcc15`
  (`default-repos`) as patch files in `toolchain/patches/`, not as edits of bebbo's tree.
- No `LICENSE` files for our own code (owner rule 2026-10-06). Where a repo has no
  `README.md`, add one whose first line says what the repo is.
- dctelnet-vtcon: `LICENSE` keeps its title, then: "DCTelnet has no licence file. The
  owner states (2026-10-06) that it is free and open source; no specific licence has been
  chosen." Nothing more.
- screen-amiga: note (found 2026-10-06) the git repository already exists, at
  `screen-amiga/src` (origin `spotUP/screen-amiga`); no `git init` was needed.
- vtcon `dist/LICENSES.txt`: one file listing each shipped part, its licence and
  where its source is (ixemul GPL/LGPL, coreutils, bebbosshd, curl, Unifont OFL,
  Twemoji CC-BY, wasabi MIT, Python, Neovim, tmux, screen), generated from
  `upterm-ports` `SOURCES.txt` where one exists.

Automated verification: `for r in <repos>; do git -C $UPTERM_ROOT/$r rev-parse
HEAD && test -f $UPTERM_ROOT/$r/README.md; done` exits 0; `git -C screen-amiga remote -v`
shows a remote; `make dist` kit contains `LICENSES.txt`.
Success: every repo in `repos.lock` clones, builds its own checks, and has a README first line; the kit lists its third-party parts.

## Phase 2: The meta-repo, lock file and bootstrap

Files (new repo `upterm`):
- `repos.lock`: one line per repo: `vtcon  https://github.com/spotUP/UP-Term.git  main  <commit>`,
  for vtcon, ixemul-vtcon (`feature/ixemul-80` until merged to main), upterm-ports,
  neovim-amiga, tmux-amiga, screen-amiga, cpython-amiga, amiga-gcc, amiga-gcc15.
  dctelnet-vtcon is listed under `# optional` (it consumes vtcon, nothing consumes it).
- `bin/upterm-bootstrap [--only name...] [--update]`: for each line, clone into
  `$UPTERM_ROOT/<name>` when missing, `git fetch`, check out the pinned commit;
  refuses to touch a tree with uncommitted changes (prints the repo and the
  `git status --short` count and moves on to the next); `--update` rewrites
  `repos.lock` to the repos' current heads (a commit in the meta-repo then
  records "these versions work together").
- `bin/upterm-doctor`: checks, and prints one line each with the fix: docker
  image `ixemul-gcc295` present; `$HOME/opt/amiga/bin/m68k-amigaos-gcc` version
  6.5; `$HOME/opt/amiga16/bin/m68k-amigaos-gcc` version 16; vbcc (`vc`, `vlink`,
  `vasmm68k_mot`) on `PATH`; `lha`; `python3` at or above the version in
  `README.md` (record the measured one, 3.14); NDK 3.2R4 headers at
  `vendor/ndk-3.2r4-Include_H` or `VTCON_NDK`; each repo at its pinned commit
  (shows drift as a list, not an error).
- `README.md`: the order to build things, the six-line quick start, and which repo to
  take if you want only one part (table: repo, what it gives you, what it needs).

Automated verification: in an empty directory, `upterm-bootstrap` clones all repos
at the pinned commits (`git rev-parse HEAD` equals `repos.lock` for each);
`upterm-doctor` exits 0 on this machine; run on a copy with a dirty tree it skips
that repo and exits 1 with the repo named.
Manual verification: none that needs hardware.
Success: a fresh checkout of the meta-repo plus bootstrap yields the working tree set
that built the last kit.

## Phase 3: Remove hardcoded paths, one place for the root

Files:
- vtcon `Makefile:207,209,382,682-687`: each `$(HOME)/Code/<repo>/...` becomes
  `$(UPTERM_ROOT)/<repo>/...` with `UPTERM_ROOT ?= $(abspath ..)`; keep every
  existing variable (`IXEMUL_SRC`, `SCREEN_BIN`, `TMUX_BIN`, `PYTHON_DIST`,
  `NVIM_DIST`, `IXEMUL_LIB`, `IXNET_LIB`) so overrides keep working.
- vtcon `tools/rig/ixpty_rig.py:18`, `tools/rig/tmux_rig.py:26`,
  `tools/rig/rig.py:39`, `tools/rig/tablat.py:3`, ixemul-vtcon
  `tools/vector-audit.py:14`: read `UPTERM_ROOT` (a small
  `tools/rig/paths.py` helper in vtcon; the one reader of the variable).
  The Kickstart ROM path becomes `UPTERM_ROM` with a one-line message when unset.
- vtcon `Makefile:520,660,676`, `tools/vbcc-aos68k.cfg`: `VBCC_PREFIX ?=
  $(shell brew --prefix vbcc 2>/dev/null || echo /opt/homebrew/opt/vbcc)`.
- upterm-ports `mk/common.mk:15-16`, neovim-amiga `Makefile:8,82`,
  `tools/configure-m68k.sh:10`, `tools/check-m68k.sh:56`, cpython-amiga: same
  `UPTERM_ROOT` default.
- Wire `upterm-ports` into the kit or remove the dead comment: decision, wire it for
  grep and ncurses 6.6 only when the kit's own copies are older (the kit ships ncurses
  5.5 tools); otherwise delete the "vtcon item 1.10 consumes it" comment. Track as its
  own row in the plan for the ports (`2026-10-04-unix-tool-ports.md`).

Automated verification: `grep -rn '/Users/spot\|\$(HOME)/Code' <repos>` (excluding
`build*`, `vendor`, `thoughts`, `.git`) returns no hit outside `README` examples;
`UPTERM_ROOT=/tmp/ws upterm-bootstrap && make -C /tmp/ws/vtcon dist` builds the kit in a
second location; the existing host suites (`make test`) and `make amiga` pass in
vtcon.
Success: the same kit builds from any directory.

## Phase 4: The kit says what it was built from

Files:
- vtcon `Makefile` `dist` rule (`688-731`): write `Files/VERSIONS` into the kit:
  one line per part: name, version, commit (read from `$(UPTERM_ROOT)/<repo>`
  `git rev-parse --short HEAD`, and `+dirty` when `git status --short` is non-empty),
  and the meta-repo commit; the build date. A dirty tree makes `make dist` print a
  warning (not an error).
- `dist/install.dos`: copy `VERSIONS` to `SYS:UP-Term/VERSIONS`; `Uninstall` removes it.
- `C:UPConsole STATUS` (device/upconsole.c, wherever STATUS is printed) prints the
  first line of `SYS:UP-Term/VERSIONS` (kit version, commit).

Automated verification: host test that the `dist` rule writes a `VERSIONS` with a line
per consumed part (`tests/test_dist_versions` or a `make dist-check` target reading
the lha listing with `lha l`); rig `install_rig.py` gains a check that
`SYS:UP-Term/VERSIONS` exists after Install and is gone after Uninstall.
Success: any installed kit can say which commits it was built from.

## Phase 5: Errors at the boundaries

Each item is a message that names the missing piece and the fix, shown where the
user is looking (stderr in a Shell, a requester from Workbench):
- `libs`: ixnet.library already refuses an ixemul.library of another version; make it a
  requester "Needs ixemul 80.1, found <version>: run the UP-Term Install".
- `uptelnet` (net/uptelnet.c): when `bsdsocket.library` is missing say "No TCP/IP stack
  running (Roadshow or AmiTCP)"; when connect fails with errno 65 (EHOSTUNREACH), 61
  (ECONNREFUSED) or 60 (ETIMEDOUT) print the meaning, not only "error N".
- `C:Claude` (claude/main_amiga.c): without AmiSSL, "needs AmiSSL 5 for talking to
  Anthropic; with ENVARC:Claude/remote set it connects to the NAS instead"; remote with
  no `uptelnet` in C: names the file.
- XCON: not mounted: the programs that open `XCON:` say "UP-Term is not installed or
  XCON: is not mounted (reboot after Install)".
- handler and library mismatch (`ACTION_VTCON_INTR`, the SIGWINCH carrier): the
  handler logs once at open (to the debug log, not to the window) which library
  version talked to it; a library that gets ERROR_ACTION_NOT_KNOWN remembers it and
  stops sending.
- Wrong CPU: the kit's programs check for a 68020 at start (the Installer already
  does); a 68000 prints one line and exits.
- `vsh`: `claude`, `ssh` and other kit commands not found on `PATH` print which drawer
  they live in (`SYS:UP-Term/bin`).

Automated verification: host tests for the message selection (a pure function per
program: given errno or missing library, the text), one rig check per program with
the condition produced (stop the network stack, rename AmiSSL, boot without XCON:).
Success: each condition above produces its named message, and no new "error N" appears.

## Phase 6: Maintain it

- Rule in vtcon `RULES.md` and each repo's rule file: a change that crosses two repos is
  one commit per repo plus one `repos.lock` update in `upterm` with the same subject line.
- `upterm-bootstrap --update` plus `make dist` is the release step; the kit's version
  is the meta-repo commit.
- CI is out of scope (the toolchain is local); `upterm-doctor` is the check run before a
  release.

## Order and size

Phase 1 (git, licences) first: nothing can be pinned before it. Phase 2 and 3 are
independent after that and take about a day each. Phase 4 is small. Phase 5 is eight
independent items; they ship as separate commits per repo and each needs a rig check.

## Not in this plan

- Merging repositories.
- Submodules.
- Telemetry or remote error reporting.
- Packaging for users who build from source on a machine other than a Mac (docker
  image for the whole build): later, after Phase 3 proves the build is
  location-independent.
