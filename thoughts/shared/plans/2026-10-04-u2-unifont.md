## Decisions (do not re-litigate)

- Source: GNU Unifont 17.0.05, `unifont_all-17.0.05.hex.gz` (sha256 7b182454...e574),
  fetched once into build/unifont/. BMP only; PUA U+E000-F8FF left out (the _all file
  carries CSUR glyphs there; Nerd Font icons live there and belong to the outline font),
  surrogates have none.
- Licence: Unifont is dual-licensed (SIL OFL 1.1, and GPLv2+ with the font embedding
  exception). The kit's pages are taken under **OFL 1.1** (no Reserved Font Name; the
  licence travels with the pages: dist/unifont/OFL-1.1.txt + SOURCE.txt).
- Page file `XX` (high byte of the code point, two upper-case hex digits), big-endian:
  0 "UFP1", 4 page, 5 version 1, 6 glyph count (u16), 8 present bits [32], 40 wide bits
  [32], 72 group offsets [8 x u16, first glyph of each 32-code-point group], 88 glyphs in
  code-point order (narrow 16 bytes, wide 32 bytes: 2 bytes a row). Max 8280 B.
- Installed to SYS:UP-Term/unifont/ (not FONTS:: FixFonts runs at install and scans it).
- Cache: UF_SLOTS = 8 pages per window, LRU, exact-size buffers; missing pages remembered
  (256-bit set) so a missing file is opened once per window.
- Drawing: window font 16 px high -> 1:1; 8 px -> each pair of rows OR'd (2:1 vertical,
  thin strokes survive); a glyph twice the target width -> pixel pairs OR'd across;
  other heights -> the replacement glyph as before. Baseline: none since W33 (2026-10-05):
  Unifont's rows are the cell's rows (was: its ascent row on tf_Baseline).
- Order (W33, 2026-10-05): native (font / drawn lines and blocks) -> outline font (F1,
  the user's choice) -> vt_map_glyph's stand-in -> Unifont (BMP + plane 1 emoji) ->
  replacement. (Was: Unifont before the stand-ins.)
- Pages read by the outline worker (DOS calls; the handler may not make them): VO_READ;
  a window without an outline font opens an engine-less worker on the first page miss.

## W33 fix + emoji (2026-10-05, ledger W33/W11) -- done, rig check open (owner)

Owner 2026-10-05: emoji as real monochrome bitmaps from Unifont plane 1 (Unifont Upper,
16x16), 2 cells wide, an optional page set with the kit's Unifont part; W33 (stand-in
cells drawn by Unifont, half height and raised on the 16-px TopazPro window) fixed first.

Decisions:
- Order: font's own / drawn -> outline font (F1, only when the profile names one; as on
  main) -> vt_map_glyph's Latin-1 stand-in ('>' for U+276F, '-' for U+2013) -> Unifont ->
  replacement ('?' / the box). Unifont never replaces a stand-in.
- 16 px = Unifont 1:1, row for row; 8 px = row pairs OR'd from row 0. No baseline shift:
  TopazPro 16 declares tf_Baseline 6 (topaz 8's, not doubled), which raised every
  Unifont glyph 7 rows and cut its top half off (the W33 "half height and raised").
- Page format UFP2: bytes 4-5 the page as u16 (cp >> 8: 0x00-0xFF the BMP, 0x1F0-0x1FA
  plane 1); names 2 hex digits (BMP) or 3 (plane 1, "1F6"). Old UFP1 pages are refused
  (absent), so a stale install shows stand-ins/boxes, never misread glyphs.
- Plane 1: only U+1F000-U+1FAFF from the same unifont_all-17.0.05 file (its plane-1
  glyphs are Unifont Upper's; same dual licence, OFL 1.1 taken). U+2600-27BF is in the
  BMP pages 26/27 already.
