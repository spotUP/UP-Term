**Phase D: console.device replacement**
- [ ] D0 KICKSTART COMPATIBILITY (owner 2026-09-28: "will we get crashes if we dont adapt it for
      all known kickstarts? is there a way around that?"). Working answer, to be proven:
      - Crashes come from depending on what a ROM version does NOT promise: private fields
        after the public `struct ConUnit`, the private device base, internal LVO order, ROM
        addresses, and SetFunction patches into ROM code. Programs that read ConUnit fields
        are the known risk; the public header fields are stable across V36-V47.
      - Way around: implement only the public contract (the device vectors in
        console_lib.fd, the public ConUnit, documented commands and units), keep the ROM
        device open and DELEGATE the keymap vectors (RawKeyConvert, CDInputHandler) to it
        instead of reimplementing them, install through Exec (RemDevice / AddDevice of our
        own node, reversible) rather than patching ROM code, and branch on
        `lib_Version` at runtime only where the public behaviour really differs by version.
      - Scope is 3.x (owner decision): KS/OS 3.0 (V39), 3.1 (V40), 3.5/3.9, 3.1.4 (V46),
        3.2 (V47). Verify each boots and runs the Amiga-personality suite in the rig before
        D ships; record the per-version results in this ledger.
      - Also a conflict risk: third-party patches of console.device / con-handler
        (KingCON, ViNCEd, MCP, NewEdit-style SetFunction patches). Detect at install time and
        refuse with a message rather than stack on top.
