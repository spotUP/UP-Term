## Owner questions (answer before K2-2; K2-1 needs none of them)

1. **Userland in the base: whole, or split by package?** You wrote "coreutils +
   minimal userland". Options:
   - A. The whole ports userland stays in the base (15.0 MB staged, 5.9 MB lha).
   - B. Split along upterm-ports packages: the base keeps grep, sed, awk, less,
     findutils, diffutils, patch, nano, mandoc (man and UP-Term's own pages),
     gzip, ncurses tools; a sixth archive UP-Term-Unix takes file (+3.4 MB magic
     data), libarchive (tar, cpio, bsdcat, bsdunzip), xz, bzip2, zip, ncdu, tree,
     watch, fzy, script (about 7.5 MB staged, about 3 MB lha, estimated from the
     per-file sizes; not measured as an archive).
   Recommended: **A**, because with Neovim, Python and the coreutils source out
   the base is already down from 34.8 MB to about 12.6 MB lha, and B costs a
   `kit-stage` change in upterm-ports (two staged sets), a sixth Installer and
   Uninstall, and a dependency the bash tools of Claude and amiga-pi would hit
   (models call `tar`, `file`, `xz`) for about 3 MB.
2. **The coreutils source tarball (4.9 MB, 5.0 MB lha) moves from the base
   archive into UP-Term-src.lha?** Recommended: **yes**, because GPL v2 section 3
   accepts equivalent access to the source from the same place, which is how the
   ports' source is already published (plan D2: UP-Term-src.lha next to the
   kit); it is the single largest cut of the base after Neovim and Python.
   Risk: whoever mirrors only UP-Term.lha ships coreutils without its source.
3. **What counts as "needs UP-Term" for the name?** K2-1 measures each add-on
   in a ROM CON: window and in KingCON. Code already says (see Facts): C:Claude
   and amiga-pi fall back to the line mode outside an UP-Term window and to the
   AmigaShell without vsh. Recommended rule: **an add-on is standalone (own name,
   no base check) only when, without the base, it starts, finishes a
   conversation with a tool call, and its keys work in both consoles; a line
   mode counts as working, a garbled screen or a missing library does not.**
   Neovim and Python are expected to need the patched ixemul (UP-Term-*);
   Claude and amiga-pi are the open ones.
4. **Version numbers.** Today the kit has none (VERSIONS line 1 is
   `UP-Term <commit> <date>`). Recommended: **every archive gets
   `<major>.<minor>` in dist/packages.txt, first release 1.0 each; an add-on
   names the lowest base version it needs; minor goes up per release, major when
   an add-on needs something the base did not have before.** Upstream versions
   (Neovim 0.12, Python 3.14, pi 1.1.0) go in each Aminet readme's Short line and
   README, not in the number.
5. **amiga-pi has no licence file of its own** (carried from K1). Blocks the
   Aminet upload of the pi archive, not its build. Needs your licence choice.
6. **Aminet directories.** Recommended: base `comm/term`, UP-Term-nvim
   `text/edit`, UP-Term-python `dev/lang`, Claude and amiga-pi `comm/misc`, the
   source archive `comm/term` beside the base. Your upload; the readmes are
   generated (K2-9).

### Where the rest goes, and why (decided)

- **coreutils (bin, 2.4 MB):** base. vsh's PATH, the `bash` tool of Claude and
  amiga-pi, and the kit's own vsh scripts (reassign.sh, unstartup.sh) assume
  them; the AmigaDOS Shell keeps C:Sort/Date/Join because they are in
  UP-Term:bin, not C:. Its source: question 2.
- **ports userland:** base, whole (question 1, recommended A).
- **net (ssh/scp, bebboget, curl; 4.6 MB staged, 2.4 MB lha):** base, as the
  Installer's optional ticks today. ssh into a Unix machine is what a modern
  terminal is for; they are other authors' programs, and publishing them as an
  archive of our own name would be wrong (naming rule) while an archive without
  them would leave the terminal without its main remote use.
- **tmux, screen (1.5 MB staged, 0.8 MB lha):** base. They need PTY: and the
  patched ixemul's ptys and job control; they are part of the terminal.
- **Unifont, emoji:** base (optional ticks as today): the handler draws from them.

## Design

### D1. One package table: dist/packages.txt

```
# The archives `make dist` writes. Columns: two or more spaces apart.
# id      archive          version  needs-base  ixemul  record                       paths handed over by the base
base      UP-Term          1.0      -           -       UP-Term:                     -
claude    UP-Term-Claude   1.0      1.0         -       UP-Term:pkg/UP-Term-Claude   Files/Claude,Files/ClaudeCode
pi        UP-Term-pi       1.0      1.0         -       UP-Term:pkg/UP-Term-pi       Files/amiga-pi
nvim      UP-Term-nvim     1.0      1.0         80      UP-Term:pkg/UP-Term-nvim     Files/nvim
python    UP-Term-python   1.0      1.0         80      UP-Term:pkg/UP-Term-python   Files/python3
```

A standalone package (K2-1 + question 3) gets its own archive name, `-` in
needs-base, and record `ENVARC:uppkg/<archive>`. Everything below reads this
file through `tools/pkgs.py`: the Makefile, mkkit, the Installer and Uninstall
templates, mkmanifest's handed lines, the tests, install_rig's cases, the readmes.

### D2. Archive layout

Each archive unpacks to one drawer named like the archive (`UP-Term/`,
`UP-Term-nvim/`, ...): Install, Install.info, Uninstall, Uninstall.info,
README.txt, LICENSES.txt, Files/. Kit paths of moved files stay what they were
in the single kit (`Files/nvim/...`, `Files/python3/...`, `Files/Claude`,
`Files/ClaudeCode`, `Files/amiga-pi`) and so do their part names (`copy-nvim`,
`copy-python`, `python`): a single kit's manifest lines compare 1:1 with an
add-on's (migration, D7).

### D3. Records: what an install leaves for Update and Uninstall

- Base: unchanged (UP-Term:MANIFEST, UP-Term:VERSIONS, ENVARC:up-term/opts),
  plus UP-Term:UP-Term.version (`$VER: UP-Term 1.0 (13.10.2026)`) for the add-ons'
  base check, plus UP-Term:pkg/legacy/{MANIFEST,VERSIONS} when it was installed
  over a single kit (D7).
- Add-on: its record drawer (table column) holds MANIFEST, VERSIONS, opts/ and a
  copy of its Uninstall. Neovim's manifest is about 2100 lines (140 KB): it stays
  out of ENVARC: (copied into RAM at every 3.1 boot); only a standalone add-on,
  whose manifest is a few lines, keeps its record in ENVARC:uppkg.

### D4. Shared code, assembled at build time

`tools/mkinstaller.py` expands `; @include <path>` lines and `@NAME@` values (from
packages.txt and the package's own values) into the kit's Install, install.dos
and Uninstall. Fragments in `dist/common/`:

| Fragment | Language | From | Used by |
|---|---|---|---|
| requirements.installer | Installer | Install.installer:41-52 (OS, CPU, Files drawer, UP-Term volume) | all |
| procs.installer | Installer | Install.installer:369-459 (P_LEAD, P_OPT, P_OPTIONS_END, P_BAR, P_WANT, P_STEP, P_COPY) | all |
| update.installer | Installer | Install.installer:64-91, record path, old manifest and ONLY= as values | all |
| check.installer | Installer | new: runs part `check`, aborts with ENV:UPTCHECK | add-ons |
| amissl.installer | Installer | Install.installer:150-151 | base (curl), Claude, pi |
| check.dos | AmigaDOS | new (snippet below) | add-ons |
| record.dos | AmigaDOS | install.dos `Lab record`, record drawer as a value | add-ons |
| uninstall-var.dos | AmigaDOS | Uninstall:92-117, `@VARDIR@` | base (UP-Term:var), Claude (var/Claude), pi (var/amiga-pi) |

`check.dos`:

```
Lab check
; what this add-on needs, before anything is copied; the reason goes to
; ENV:UPTCHECK, which the Installer's abort page shows
Delete >NIL: ENV:UPTCHECK QUIET
If NOT "@NEEDSBASE@" EQ "-"
  Assign >NIL: UP-Term: EXISTS
  If WARN
    Echo >ENV:UPTCHECK "@ARCHIVE@ needs UP-Term @NEEDSBASE@ or newer. Install UP-Term.lha first."
    Quit 20
  EndIf
  Version >NIL: FILE UP-Term:UP-Term.version @BASEMAJOR@ @BASEMINOR@
  If WARN
    Echo >ENV:UPTCHECK "@ARCHIVE@ needs UP-Term @NEEDSBASE@ or newer. Update UP-Term first."
    Quit 20
  EndIf
EndIf
If "@IXEMUL@" EQ "80"
  Version >NIL: LIBS:ixemul.library 80
  If WARN
    Echo >ENV:UPTCHECK "@ARCHIVE@ needs UP-Term's ixemul.library 80 in LIBS:. Install UP-Term again."
    Quit 20
  EndIf
EndIf
If NOT "{STEP}" EQ ""
  Quit 0
EndIf
```

A single kit has no UP-Term:UP-Term.version, so an add-on over it says "Update
UP-Term first": the migration order is base first (D7).

`check.installer`:

```
(set #rc (execute "UPTKIT:install.dos" "UPTKIT:" "STEP=check"))
(if (>= #rc 20)
    (
        (P_OPTIONS_END)
        (abort (getenv "UPTCHECK"))))
```

### D5. User data (one rule set, tested once for every package)

- Install and Update never write inside UP-Term:var, never write a file in
  ENVARC:amiga-pi, and write in ENVARC:Claude only `remote` when an address is
  given (as today).
- Uninstall of an add-on keeps ENVARC:<program> and asks about its own
  UP-Term:var/<program> (default No, `upvardelete` answers for a script); base
  Uninstall asks about the whole UP-Term:var as today.
- A host test (`tests/test_dist_userdata.py`) reads every assembled install.dos
  and Uninstall and fails on a write (Copy/Echo >/Delete/MakeDir) into those
  places outside the allowed lines. It replaces test_dist_installer.py's
  AmigaPiInstall pair (:214,:218).

### D6. Uninstall per package

- Add-on Uninstall (template `dist/common/uninstall-addon.dos`): its body
  (`dist/addons/<id>/uninstall-body.dos`: its files, its S:User-Startup block),
  then uninstall-var.dos, then `Delete "@RECORD@" ALL`.
- Python's block: `unstartup.sh` takes an optional block name and removes only
  `;BEGIN UP-Term <name>` .. `;END UP-Term <name>`; with no name it removes every
  block, as now (the Replay case of an older copy, unstartup.sh:4-6).
- Base Uninstall runs the Uninstall of every UP-Term-* add-on whose record is
  there, first, while UP-Term: is still assigned (generated from packages.txt):

```
; the add-ons that need UP-Term go first, each by the Uninstall its Install kept
If EXISTS UP-Term:pkg/UP-Term-nvim/Uninstall
  Execute UP-Term:pkg/UP-Term-nvim/Uninstall
EndIf
; (one block per add-on, from dist/packages.txt)
; a single kit's add-on files that no add-on took over (UP-Term:pkg/legacy, D7)
If EXISTS UP-Term:pkg/legacy
  If NOT EXISTS UP-Term:pkg/UP-Term-Claude
    Delete >NIL: C:Claude C:ClaudeCode QUIET
  EndIf
  If NOT EXISTS UP-Term:pkg/UP-Term-pi
    Delete >NIL: C:amiga-pi QUIET
  EndIf
EndIf
```

  and `C:Claude C:ClaudeCode C:amiga-pi` leave its fixed delete list (Uninstall:147).
  A standalone add-on is left alone by base Uninstall.

### D7. Migration from the single kit (old layout recognised)

Order: base first, then add-ons.
1. The new base's manifest carries one line per handed path
   (`handed 0 00000000 handed#Files/nvim`), written by mkmanifest from packages.txt.
2. updiff: a gone old line under a handed path is skipped: no Delete line, no
   part run, not counted. upupdate sets ENV:UPTHANDED to the archives whose
   files it kept; the base Update page then says "Neovim, Python, Claude and
   amiga-pi stay installed; they are separate archives now: install
   UP-Term-nvim (...) to update them."
3. The base's `record` part, before it replaces UP-Term:MANIFEST: an old
   manifest that names a handed path is the single kit's; it is kept once:

```
Lab record
; installed over the single kit (before the split): its manifest and VERSIONS
; are kept in UP-Term:pkg/legacy, where an add-on's Update finds its files
If EXISTS UP-Term:MANIFEST
  If NOT EXISTS UP-Term:pkg/legacy/MANIFEST
    Set uplegacy ""
    ; @HANDEDSEARCH@ expands to one Search per handed path:
    Search >NIL: UP-Term:MANIFEST " Files/nvim/"
    If NOT WARN
      Set uplegacy YES
    EndIf
    If "$uplegacy" EQ "YES"
      MakeDir >NIL: UP-Term:pkg UP-Term:pkg/legacy
      Copy UP-Term:MANIFEST UP-Term:VERSIONS UP-Term:pkg/legacy CLONE QUIET
    EndIf
    UnSet uplegacy
  EndIf
EndIf
Copy MANIFEST UP-Term:MANIFEST CLONE
```

   (the Shell route runs `record` too, so a Shell install over a single kit is
   recognised the same way).
4. An add-on's Install with no record of its own and UP-Term:pkg/legacy/MANIFEST
   there runs `upupdate UP-Term:pkg/legacy/MANIFEST <its MANIFEST> <kit>
   ONLY=<its handed paths>`: upupdate keeps only the old lines under those paths,
   so the Update page offers Update from "installed by the single UP-Term kit"
   and copies only what changed.

### D8. Versions and VERSIONS

- packages.txt's version is the archive's version. `tools/mkkit.py` writes
  `Files/UP-Term.version` for the base (`$VER: UP-Term 1.0 (13.10.2026)`, which
  install.dos's `tools` part copies to UP-Term:) and passes the version to
  mkversions.
- `tools/mkversions.sh [--package <archive> <version>] [UPTERM_ROOT] [part ...]`:
  line 1 becomes `<archive> <version> <vtcon commit> <date> (upterm <meta>)`, then
  the parts given (default: today's list, so a call without arguments is
  unchanged). Parts per archive: base `vtcon ixemul-vtcon upterm-ports tmux-amiga
  screen-amiga/src`; Claude `vtcon`; pi `amiga-pi vtcon`; nvim `neovim-amiga
  ixemul-vtcon`; python `cpython-amiga ixemul-vtcon` (pkgs.py column, not a
  second list in the Makefile).

```python
INC = re.compile(r'(?m)^; @include (\S+)[ \t]*\n')

def assemble(path, values, stack=()):
    """The template with each ; @include line replaced by its file (values
    substituted first, so a path may hold @ID@), and every @NAME@ by its value."""
    if path in stack:
        raise SystemExit('mkinstaller: %s includes itself' % path)
    text = sub(path.read_text(encoding='latin-1'), values)
    text = INC.sub(lambda m: assemble(ROOT / m.group(1), values, stack + (path,)), text)
    left = sorted(set(re.findall(r'@[A-Z0-9]+@', text)))
    if left:
        raise SystemExit('mkinstaller: %s: no value for %s' % (path, ' '.join(left)))
    return text
```
