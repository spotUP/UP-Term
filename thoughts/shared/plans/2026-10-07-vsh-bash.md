# bash for Amiga: vsh to bash-level compatibility

Input: `thoughts/shared/research/2026-10-07_vsh-bash-gap.md` (the gap audit, called "the audit"
below; its probe ids are written `P:name`). Code: `shell/sh_parse.c` (960 lines),
`shell/sh_expand.c` (919), `shell/sh_exec.c` (2732), `shell/vsh.c` (1608, the Amiga OS layer),
headers `shell/sh_*.h`; host tests `tests/test_sh_parse.c`, `tests/test_sh_expand.c`,
`tests/test_sh_exec.c` (suites `sh_parse`, `sh_expand`, `sh_exec` in `tests/test_main.c:64-66`).
Line counts measured 2026-10-07 with `wc -l`.

## Decisions

Owner decisions (final, 2026-10-07):

- **bash behaviour is the default in vsh.** No `--bash` mode. A POSIX-strict switch exists and is
  bash's own: `set -o posix`, `--posix`, `POSIXLY_CORRECT` (V80). No invented third dialect.
- **fd > 2: shell-internal fd table only.** Builtins, functions and compound commands see fds 3
  and up; external commands get fds 0-2 only (a redirection such as `cmd >&3` still works, because
  it maps fd 1 of `cmd` onto the handle fd 3 holds). Documented divergence.
- **Process substitution: temp file first** (`T:`, falling back to `RAM:` when `T:` is not
  assigned); `PIPE:` later, not in this plan.
- **Console-handler features last** (vi mode, `bind`, programmable completion, history packet):
  Phase 7.
- **Case-insensitive globbing is an option**, `shopt nocaseglob`.

Decisions made in this plan (owner may veto):

- **`nocaseglob` default: ON on the Amiga, OFF on the host driver and under `set -o posix`.**
  Reason: AmigaDOS filesystems are case-insensitive, so `cat readme` already opens `README`; a
  case-sensitive `*.c` that misses `MAIN.C` would make globs the one lookup that disagrees with
  the filesystem. `case` and `[[ == ]]` stay case-sensitive (`nocasematch` off), as today
  (`sh_expand.c:779` is the only `nocase` user). The cost, documented: `[a-z]*` also matches
  `Makefile` on the Amiga.
- **Phase order changed from the audit: the typed variable store moves from 5th to 2nd**, before
  expansions, arithmetic and `[[ ]]`. Reason: every later phase writes code that must address
  array elements: `${a[@]/x/y}`, `${a[@]:1:2}`, `${!a[@]}` (P3), `a[i]++` and `(( m[k] += 1 ))`
  (P4), `BASH_REMATCH` for `=~` (P4), `PIPESTATUS`, `FUNCNAME`, `DIRSTACK` (P2, P6), `mapfile`,
  `read -a`. Written scalar-first, each of those needs a second pass; `local` scoping
  (`saved_var` in `sh_exec.c`) would be rewritten twice. The audit's own open question 4 says
  "do it once, before phases 2-6 touch it". The fd table moves to 5th: only `configure` and a
  minority of scripts need it, the agent subset does not.
- **`kill` moves into Phase 1** (agents run `kill %1` / `kill $pid` after a background server);
  the `history` builtin moves into Phase 7 (its data lives in the console handler).
- **Arithmetic is 64-bit** (V61): epoch milliseconds (`$(( $(date +%s) * 1000 ))`, 1.7e12)
  overflow 32 bits, and agents compute them.
- **`=~` reuses `claude/regex.c`** (873 lines, Pike VM, linear time, C89, host-tested in
  `tests/test_claude_match.c`) instead of a second regex engine; it gains capture groups and a
  POSIX flag (V66).
- **`globstar` reuses `claude/glob.c`**, which already matches `**` (`claude/glob.h:2,19`), after
  checking its semantics against bash's (V79).
- **`lastpipe` default off, as in bash** (V79): the last pipeline stage runs in a clone when it is a
  builtin, function or compound command (state changes must not leak: `cat f | while read l; do
  n=$((n+1)); done; echo $n` prints 0 in bash); an external last stage keeps running from the
  shell (no observable difference, no extra process). Cost on the Amiga: one clone process for
  pipelines ending in a loop or builtin.
- **Associative array iteration order:** keys kept in a sorted vector (memory-frugal, no hash
  table). bash's order is its own hash order; probes that list keys pipe through `sort`.
  Documented divergence.
- **`export -f`**: not implemented (no child bash reads `BASH_FUNC_*` on the Amiga). Divergence.
- **Compatibility target:** the oracle's behaviour (bash 5.3.9, measured) for every feature bash
  5.2 has; features new in 5.3 (for example `${ cmd; }` function substitution) are out of scope.
- **Size budget** (my default): `build/amiga/vsh` is 78,240 bytes today (measured, build of
  2026-10-07 08:26). Per-phase growth budget: P1 +14 KB, P2 +10 KB, P3 +12 KB, P4 +16 KB (regex
  included), P5 +4 KB, P6 +14 KB, P7 +8 KB (vsh only; handler measured separately); ceiling about
  160 KB. Idle heap after startup grows by at most 4 KB over the P0 baseline. vsh already
  requires a 68020 (`cpuchk-vsh.o`, `Makefile:312`), so the target is 68020+, not a 68000.

Residual owner decisions: see the end of this document.

## Constraints (every phase)

- No regression: `make test` passes with suite `sh_exec` at 312 checks or more and 0 failures (312
  is the brief's figure; a grep of `CHECK`/`check(` spellings in `tests/test_sh_exec.c` gives 293,
  a spelling count, so the suite's printed count is the gate; not re-measured for this plan);
  `sh_parse` and `sh_expand` suites likewise keep their printed counts. `userland_rig.py`: every
  package whose verdict is PASS stays PASS.
- vsh is vbcc C89 (`Makefile:241`, `-warnings-as-errors`); the shell core also passes the host lint
  at `Makefile:66` (`-std=c99 -Wall -Wextra -Werror -Wdeclaration-after-statement`).
- Memory-frugal: no hash tables where a sorted vector does, no per-node growth beyond one `int`,
  heap freed on unset, recursion depth guarded by the existing `stack_limit`.
- Reuse before writing: the escape decoder of `printf %b` (`sh_exec.c:571-700`), the here-doc
  temp-file mechanism (`sh->heredocs`), `claude/regex.c`, `claude/glob.c`, `shell/ixkill.c`, the
  "answered ERROR_ACTION_NOT_KNOWN, not asked again" pattern (commit 3e6eff6).
- Only affected probes are re-run while working (`--only AREA`, `--failed`); a full corpus run
  needs a stated reason (phase landing, a change to a shared function such as `sh_expand`).
  `userland_rig.py` is a full run at each phase end, with the reason: vsh is the runner of every
  userland case, so every vsh change reaches all of them.

## Test design: the differential harness (Phase 0)

There is no standalone host vsh today: `make test` builds `build/vttest_host`, which drives the
shell core through a fake OS in `tests/test_sh_exec.c`; the audit's driver lived in a scratchpad
and is gone (audit, Method). Phase 0 builds a permanent one.

- **`tests/vsh_host.c`** -> `build/vsh_host`: `main` plus a POSIX `sh_os` implementing every
  callback `vsh.c` sets (`vsh.c:1275-1296`: open, close, pipe, run, wait, done, cont, isatty,
  stack, umask, spawn (fork + `sh_run_child`), read, interrupted, write, read_line, chdir, cwd,
  exists/stat, listdir via `readdir`). External commands get an `envp` built from vsh's exported
  variables (`execve`), not the host environment: the audit's driver leaked the host environment,
  which left `export` and `A=1 cmd` unconfirmed. `ctx.nocase = 0`.
- **Oracle:** `$BASH_ORACLE`, default `/opt/homebrew/bin/bash` (5.3.9, measured). **`/bin/bash` on
  this Mac is 3.2.57 (measured) and must not be the oracle**; the runner refuses an oracle whose
  `BASH_VERSINFO[0]` is below 5.
- **Probe corpus:** `tests/bash/probes/<area>/<name>.sh`, optional `<name>.in` (stdin) and
  `<name>.args` (argv). Fixture tree `tests/bash/data/` (lowercase names only, so the Amiga's
  `nocaseglob` and bash agree). Areas: `options invocation test builtins arrays expand redir
  procsub arith dbrack fd traps shopt jobs interactive agent`.
- **Runner `tools/bashdiff.py`:** for each probe, copy `tests/bash/data` into a fresh temp dir,
  run `env -i PATH=<fixed> HOME=<tmp> LANG=C LC_ALL=C TZ=UTC <shell> <probe> <args> < <in>` under
  the oracle and under `build/vsh_host`, 5 s timeout each; compare stdout bytes and exit status
  (stderr is not compared; a probe that needs it writes `2>&1`). Writes the oracle's output as
  `build/bashdiff/expected/<area>/<name>.txt` in `userland_rig.py`'s format (stdout, then a last
  line `[exit N]`), so the rig reuses it. Verdicts in `build/bashdiff/<area>.verdict`: first line
  PASS/FAIL plus a fingerprint (probe hashes, `vsh_host` hash, oracle version), then one line per
  probe. Resumable: a passed probe with an unchanged fingerprint is skipped. Flags: `--only AREA`,
  `--probe NAME`, `--failed`, `--force`, `--gate`. Prints the summary and failing names only;
  diffs go to `build/bashdiff/diff/`.
- **`tests/bash/divergences.txt`:** `probe-id <TAB> class <TAB> reason`, class one of
  `n/a-amiga` (impossible on AmigaOS, reason says why), `documented` (a decision above), or
  `later:Vnn` (removed by item Vnn). The runner fails when a `later:` entry names an item ticked
  in this plan (read from this file's checklist).
- **`tests/bash/ratchet.txt`:** probe ids that must be identical. Each phase adds its probes.
  `make bashdiff` runs the runner; `make test` gains a final step `tools/bashdiff.py --gate`
  (ratchet probes only, resumable, so a clean tree costs seconds) and prints `[INFO] no bash 5`
  and skips when the oracle is missing.
- **Reachability sentinels:** host builds compile `-DSH_HITS`: a counter array indexed by an enum
  of feature hooks (errexit fired, pipefail used, `[[` evaluated, fd>2 resolved, ...), dumped by
  `vsh_host --hits` to stderr. Compiled out on the Amiga (zero bytes). Each phase has ONE
  reachability probe through `vsh_host` (the top-level entry: `main` -> `sh_run_text`) asserting
  its counters; every other behaviour is a probe or a unit test where it lives.
- **Rig:** `tools/rig/userland_rig.py` gains a second case source, `--bash AREA [--case NAME]`:
  it stages `tests/bash/probes/AREA` and `tests/bash/data` to `VTC:`, runs `VTC:vsh <probe>` with
  stdout to `VTC:out/bash/AREA/<name>.txt` (existing `run_case` shape, `userland_rig.py:133`),
  compares against `build/bashdiff/expected/...`, and keeps verdicts and fingerprints the existing
  way (`read_verdict`/`write_verdict`). `tests/bash/rig-skip.txt` lists host-only probes with a
  reason. The rig's EXEC takes no `<` redirect (`userland_rig.py` docstring), so `.in` probes are
  rewritten as a here-doc wrapper by the stager.

## Agent subset and the amiga-pi milestone (M-pi)

amiga-pi's `bash` tool runs `vsh -c "<command>"` (amiga-pi plan, decision 5,
`thoughts/shared/plans/2026-10-07-amiga-pi.md:706-710`), replacing its earlier AmigaDOS `shell`
tool (items D3, D7). The model writes bash for that tool. The minimal subset it needs is what a
coding agent's commands contain:

- `vsh -c` contract: exit status of the last command (with `set -o pipefail` honoured), stdout and
  stderr kept separate, a break (Ctrl-C / timeout) ends the command and returns 130.
- `cd dir && cmd`, `;`, `||`, pipes, `2>&1`, `2>/dev/null`, `&>`, `&>>`, `>|`, `|| true` (works today).
- `set -e`, `set -u`, `set -x`, `set -o pipefail`, `set -euo pipefail`; `bash -c`-style flags
  `-c -ec -xc` (V13-V20).
- Here-docs `cat > f <<'EOF'`, `<<-`, `<<<` (V58).
- `test`/`[` complete, `[[ ]]` with `== != =~ < > -f -d -x -z -n && || !` (V21, V22, V65, V66).
- `$(( ))` full operator set, 64-bit; `(( i++ ))`; `for (( i=0; i<n; i++ ))` (V61-V64).
- `${x:-d}` (works), `${x%/*}` (works), `${x/a/b}`, `${x//a/b}`, `${x:0:3}`, `${x^^}`, `${!x}`,
  `${#a[@]}`, `$'..'`, brace expansion `{a,b}` `{1..5}`, `$(<f)`, `[[:alpha:]]` (V46-V56).
- Indexed arrays `a=(..)`, `"${a[@]}"`, `a+=(..)`, `${a[i]}`, `declare -a`, `local` (V34-V37, V40).
- `echo -e`, `printf -v`, `printf %q`, `command -v`, `type -t`, `readonly`, `declare`,
  `x+=`, `return N`, `. file args`, `kill`, `function name {}` (V23-V29, V31, V57).
- Process substitution `diff <(a) <(b)` (V59).

Every item that realises the subset carries the tag **[pi]** in its text. **M-pi = all [pi]
items ticked plus V69.** Execution order (the one allowed reordering inside phases): P0, then the
[pi] items of P1-P4 in phase order, then gate V69, then the untagged items of P1-P4 in phase order,
then P5-P7. The plan is not done until every item is ticked; M-pi only unlocks amiga-pi.

**The agent corpus** (`tests/bash/probes/agent/`, V8) is the M-pi measure: at least 80 probes,
each a command in the shapes above, written as the model writes them, for example
`set -euo pipefail; for f in src/*.c; do [[ -f "$f" ]] && wc -l "$f"; done | sort -n | tail -3`,
`if command -v gcc >/dev/null 2>&1; then echo yes; fi`, `cat > out.txt <<'EOF' ... EOF`,
`diff <(sort a) <(sort b) || true`, `n=$(( $(wc -l < f) * 2 )); echo "${n}"`,
`files=( *.txt ); echo "${#files[@]} ${files[0]%.txt}"`, `x="a-b-c"; echo "${x//-/_}" "${x^^}"`,
`[[ $v =~ ^([0-9]+)\.([0-9]+)$ ]] && echo "${BASH_REMATCH[2]}"`.

## Phase 5: File descriptors above 2 (shell-internal table)

Files: `shell/sh_exec.h` (`sh_io`), `shell/sh_exec.c` (`redirect`, `exec`, builtins writing to
fds, `read -u`, `mapfile -u`), `shell/sh_parse.c` (`n>`, `{var}>` tokens), `shell/vsh.c`,
`tests/test_sh_exec.c`.

Design: `sh_io` keeps `in, out, err, owned` and gains one pointer `struct sh_fdtab *xfd` for fds 3
and up: copy-on-write and reference-counted, so the many `sh_io` copies on the interpreter's stack
stay small. AmigaDOS has no `dup`: `3>&1` makes fd 3 share fd 1's handle, so handles get a small
registry with reference counts and a handle is closed only when its last reference goes (this
replaces the `SH_OWN_*` bits' job for fds 3+; fds 0-2 keep the bits, avoiding churn in 2,732
lines). One accessor `sh_fd_get(io, n)` serves every user.
