# amiga-pi: implementation plan

Input: `thoughts/shared/research/2026-10-07_pi-like-amiga-agent.md` (all of it; section
numbers below as "R3.6" refer to it). Repo: vtcon, branch `main`, HEAD 5c68bba at writing.
Line numbers in C:Claude's sources are the research's; `claude/http.c:109-126` and
`Makefile:276-301` were re-checked at 5c68bba, the rest were not.

Nothing in this plan was run. No rig, no Amiga.

## Decisions

Owner decisions (2026-10-07, final):

- Scope: all of pi's feature set, in phases. New program `amiga-pi` sharing C:Claude's core.
  C:Claude stays unchanged in behaviour and green: `make test` (all `test_claude_*`),
  `make claude-tls-check`, and the fixture's existing `/v1/messages` routes.
- Reuse C:Claude's `json.c`, `sse.c`, `http.c`, `tls_*.c`, `net_*.c`. No JSMN, no rewrite.
- Stored format: pi's message model (pi-ai content blocks and roles) and pi's JSONL session
  format version 3.
- Permissions: pi's default (never ask). C:Claude's ask-before-acting gate is a built-in,
  switchable extension (off by default).
- Extensions: first the existing hook commands (`claude/hooks.c` mechanism), then Lua 5.4
  or native modules, decided by the one-day vbcc probe A5 with the criterion in A5. No
  Python, no JS runtime.
- Plain `http://` allowed for LAN endpoints; an API key is never sent over plain http.
- Provider order: Anthropic (exists), OpenAI-compatible (phase B: backend interface,
  adapter, provider-neutral LLM event model after pi-ai), then Google, Azure, Bedrock.
- Subscription logins (Claude Pro/Max, ChatGPT, Copilot): last phase, gated on a
  device-code-flow feasibility probe (O1).
- Milestone 0 deliverables `amiga-pi/ARCHITECTURE.md` and `amiga-pi/COMPATIBILITY.md`.

Decisions made in this plan (the owner can veto):

- **Layout.** Shared provider-neutral LLM layer in a new top-level `llm/` directory
  (the repo's one-directory-per-component convention: `claude/`, `net/`, `tty/`). The
  program in `amiga-pi/`. Transport stays in `claude/` (`net.h`, `tls.h`, `http.h`,
  `sse.h`, `json.h`) and is linked by both programs. Agent dir `ENVARC:amiga-pi/` (pi:
  `~/.pi/agent/`); project resources in `<root>/.pi/` (pi's name kept, so a project
  works with pi on the Mac too).
- **Sharing the Anthropic wire code.** The Anthropic request head (`http.c:109-126`) and
  the event decoder (`stream.c:194 stream_event`) move behind the backend interface in
  `llm/be_anthropic.c`; C:Claude's `stream.c` becomes a consumer of the neutral event
  stream that rebuilds its `sblock`s. Gate: every existing `tests/test_claude_*` passes
  with no edit to the test files and the request bytes equal a golden captured before
  the move (B4). The other choice -- leave C:Claude on its own decoder and write a
  second Anthropic decoder -- duplicates the decoder, which the rules forbid.
- **Layering rule, enforced by a check (A4):** UI -> agent -> LLM -> HTTP -> TLS ->
  bsdsocket. `llm/` includes no `ui.h`/`tui.h`/`sys.h`; `claude/http.c` contains no
  provider name; `llm/be_*.c` include no AmigaDOS or `sys.h`; `amiga-pi/` UI files
  include no `net.h`/`tls.h`.
- **LAN rule.** A `http://` URL is accepted only when the resolved peer address is
  loopback (127/8), private (10/8, 172.16/12, 192.168/16) or link-local (169.254/16);
  decided on the address `cl_net` connected to, not the name. On `http://` no
  credential header is written at all; a configured key for that provider is dropped
  with one notice per provider per run ("key for <provider> not sent: plain http").
  pi's own Ollama example sets `apiKey: "ollama"`, so refusing would break copied
  `models.json` files; dropping satisfies "never sent".
- **Tool names.** pi's `read`, `write`, `edit`, `grep`, `find`, `ls` as pi names them.
  pi's `bash` becomes `shell` (AmigaDOS Shell through `sys->run`); a model told "bash"
  writes Unix commands. Session roles and RPC names keep pi's spelling (`bashExecution`,
  `bash`, `abort_bash`, `user_bash`) so files and clients stay compatible. Recorded in
  COMPATIBILITY.md.
- **Phase letters are the checklist prefixes** (A = milestone 0, B = milestone 1, ...).
- **TUI parity (phase N)** is placed after the providers; the interactive prompt from
  phase C (C:Claude's `tui.c`/`input.c` as they are) carries until then.

## Every phase

- Host tests in `make test` (`build/vttest_host`, C89 pedantic, ASan/UBSan), new suites

## Phase B -- Milestone 1: network/LLM vertical slice

Goal: a provider-neutral request/stream path, Anthropic moved behind it with C:Claude's
behaviour unchanged, an OpenAI-compatible adapter, all against the fake server.

Files:
- `llm/llm.h`, `llm/llm.c`: pi-ai's model in C. Content blocks `text{text,
  textSignature?}`, `thinking{thinking, thinkingSignature?, redacted?}`,
  `image{data, mimeType}`, `toolCall{id, name, arguments, thoughtSignature?}`, plus
  `raw{api, json}` for blocks pi does not model (R3.0 pick B). Roles user, assistant
  (api, provider, model, usage, stopReason, errorMessage), toolResult (toolCallId,
  toolName, content, isError, details), system. Each message held as JSON text (jw/json
  slices, R3.10) plus a small struct (role, stop reason, tool-call index). Stop reasons
  stop|length|toolUse|error|aborted. Usage with cost.
- `llm/event.h`: neutral stream events after pi-ai: start; text/thinking/toolcall
  start|delta|end keyed by contentIndex; done{reason}; error{aborted|error, partial}.
  Failures go into the stream, never as a return path the caller must special-case.
- `llm/accum.c`: event -> assistant message accumulator (interleaved contentIndex,
  tool-call arguments parsed strictly at end, signatures byte-exact).
- `llm/backend.h`: `llm_backend { name; url(model, out); head(model, auth, out);
  secret_header; body(ctx, opts, jw*); feed(state, sse_event, sink) ; framing }`.
- `llm/be_anthropic.c`: head (from `http.c:109-126`), body from neutral messages (from
  `conv_body` logic, `conv.c:216-268`), event decoder (from `stream.c:194`).
- `llm/be_openai_chat.c`: openai-completions with compat flags `maxTokensField`,
  `supportsUsageInStreaming`, `supportsDeveloperRole`, `requiresToolResultName`
  (wire details per A3).
- `llm/pool.c`: one `cl_net` connection per host:port, at most 4 open, least recently
  used closed first.
- `llm/lan.c`: the LAN rule (pure function on a scheme and an IPv4 address).
- `llm/request.c`: connect, send, feed http -> sse -> backend, retry (pi defaults:
  3 retries, 2000 ms base, 60000 ms cap; Retry-After honoured), idle timeout 300 s,
  Ctrl+C abort -> stopReason aborted with partial content.
- Changed: `claude/http.c` (request head takes a header list from the caller; redaction
  by the backend's secret header name), `claude/stream.c` (consumer of `llm/event.h`),
  `claude/repl.c` `post` (calls `llm/request.c` with the Anthropic backend), `Makefile`
  (`LLM_CORE` list added to `CLAUDE_CORE` Makefile:33-39 and `CLAUDE_PORTABLE`
  Makefile:276-283).
- Tests: `tests/test_pi_llm.c`, recordings `tests/pi/openai_text.sse`,
