## Phase B design (2026-10-10, before the first B edit)

- llm/ in vtcon, C89, no sys.h/ui.h (check_layers). Suites tests/test_pi_llm.c (ONLY=pi_llm),
  recordings tests/pi/.
- B1 llm.h: pi-ai message JSON as the stored form; block writers (text, thinking, image,
  toolCall, raw{api,json}), message writers (user, assistant with api/provider/model/usage/
  stopReason/errorMessage, toolResult, system); llm_msg_canon re-writes any pi-shaped message
  in canonical key order (the round trip). Timestamps as {sec, ms} (68k long cannot hold ms
  since 1970); cost in micro-dollars, written as a decimal.
- B2 event.h: one llm_event struct (type, contentIndex, kind text|thinking|toolCall|raw,
  delta bytes, id/name, raw type, stop reason neutral + the provider's own, usage, error).
  accum.c builds the assistant message; strict toolCall argument parse at its end.
- B3 backend.h: {name, secret_header, path, head(headers list), body, feed state, feeds
  sentinel}. request.c: llm_post = one attempt (pool connection, send, http -> sse -> feed,
  idle, poll for abort) returning a code + detail; llm_request = pi's retry (3, 2000 ms,
  60000 ms cap, Retry-After) over llm_post, failures as events. C:Claude keeps its own
  retry/messages and calls llm_post (B5).
- B5 keeps every C:Claude API the tests use: http_request_head/http_redact (moved to
  be_anthropic.c, still declared in http.h), stream_event/stream_content (stream.c rebuilds
  sblocks from neutral events fed by the Anthropic decoder). http.c gets a generic head
  (header list) and generic redaction by header name, and no provider name.
