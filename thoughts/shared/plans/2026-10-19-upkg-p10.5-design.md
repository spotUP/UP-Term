# P10.5 design

Owner decisions (2026-10-19, session 2, in the ledger; not re-asked): the opkg binary replaces the vsh
script as UP-Term:bin/upkg now. opkg_NO_KIT goes. dist/upkg, tests/test_dist_upkg.py and the
script-only upkg_rig cases retire. The P10.5 rig test drives the real `upkg`. Known gap: add-ons
installed by the old script have no opkg status record (reinstall over them works).

## Checklist (IDs for the ledger)

- P10.5-1 upterm-ports: drop `opkg_NO_KIT := 1` (pkgs/opkg/recipe.mk:21). The kit-stage then carries
  UP-Term/bin/upkg. Check `make kit-stage` (or the repo's equivalent) puts it there.
- P10.5-2 vtcon kit: ship dist/upkg.conf as UP-Term/etc/upkg.conf, and create the empty dirs
  UP-Term/pkg/upkg/{lists,info,cache} (an empty dir needs a placeholder only if lha drops empty dirs;
  check). Wire both where Makefile:1034 copies kit files today, and in dist/install.dos so the
  Installer copies them. dist/Uninstall removes UP-Term/pkg/upkg and etc/upkg.conf.
- P10.5-3 retire the script: delete dist/upkg, its copy at Makefile:1034, tests/test_dist_upkg.py and
  its Makefile:110 hook. Fix every other reference (grep hits 2026-10-19: dist/Uninstall,
  dist/install.dos, dist/README.txt, tools/pkgs.py comments, tests/test_dist_{assemble,ipk,addons,
  packages,installer}.py, tests/test_rig_fixtures.py). tools/pkgs.py's preinst copies older() from the
  script; keep the logic, reword the comment so it no longer points at a deleted file.
- P10.5-4 README.txt: upkg usage is now opkg's (`upkg update`, `upkg list`, `upkg install <pkg>`,
  `upkg upgrade`, `upkg remove <pkg>`).
- P10.5-5 tools/rig/upkg_rig.py: rewrite the cases against the real binary. Feed: build/ipk/ served
  over http from the Mac (the script test already serves a release; reuse its server). Config: the
  test asserts UP-Term:etc/upkg.conf equals dist/upkg.conf byte for byte, then runs upkg with
  `-f T:upkg-rig.conf`, a copy whose only change is the `src/gz` line (http to the Mac; https is P10.7).
  Cases, each a recorded verdict as today:
  - version: `upkg --version` prints "based on opkg 0.9.0" (the sentinel: the opkg binary ran, not the
    vsh script).
  - update+list: `upkg update` then `upkg list` names the 4 add-ons.
  - install: `upkg install nvim`: files land (Files/install.dos ran under ixemul /bin/sh via
    Execute), status record present in UP-Term:pkg/upkg/status, T:upkg-stage holds nothing for nvim
    afterwards. This proves `dest root /` reaches T:.
  - upgrade: serve a feed with nvim's version bumped (rebuild the ipk with a bumped version in a temp
    dir, do not change the real version); `upkg upgrade` moves to it.
  - remove: `upkg remove nvim`: files gone, status record gone, no T:upkg-stage left (empty dir too).
  - needsbase: UP-Term:VERSIONS faked older than nvim's needs-base: install refused, nothing written.
    Restore VERSIONS after.
  - badsum: feed with a wrong SHA256sum in Packages: install refused.
- P10.5-6 rig run: rig 3 only (`UPTERM_RIG=3`, started `rig.py start --max`), base kit reinstalled
  from the new kit with every Installer option ticked. All cases pass. Record the commits.
