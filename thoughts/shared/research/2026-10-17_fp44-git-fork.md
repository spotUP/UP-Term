# git on AmigaOS/ixemul (no fork) - source audit
Version read: git 2.56.0 (GIT-VERSION-GEN:3, kernel.org latest 2.x). Tree: scratchpad/gitsrc/git-2.56.0
Paths below relative to that tree.

## start_command (run-command.c)
- 748 `#ifndef GIT_WINDOWS_NATIVE` selects the POSIX body; the else body (≈925-960) calls `mingw_spawnvpe` (946), defined only in compat/mingw.c. Not usable elsewhere: needs compat/mingw.h and win32 types; GIT_WINDOWS_NATIVE also redirects dozens of other things in git-compat-util.h. No NO_FORK knob exists (grep NO_FORK/HAVE_FORK/vfork/posix_spawn: zero hits).
- POSIX body: 787 `cmd->pid = fork();` child block 788-870 does ONLY: set_die/error/warn_routine (mutates globals), child_notifier global (801), dup2/close, chdir, signal() loop (856-?), sigprocmask, execve, child_die (writes errno to notify pipe, _exit). No git work that needs a continuing child. So it is vfork-shaped already, but writes parent globals (child_die_fn routines, child_notifier) and resets signal handlers (shared under vfork).
- Parent side 880-: reads notify_pipe to get exec errno -> fine with vfork (child execs first).
- atfork_prepare/parent (513-540) blocks signals around fork: harmless.

## start_async (run-command.c:1205-1260)
- `#ifdef NO_PTHREADS`: fflush, `fork()` (1209), child runs `async->proc(...)` IN-PROCESS then exit (1219-1226). Continues alongside parent: NOT vfork-able.
- else (pthreads): pthread_create (1255). No threads on target => must use NO_PTHREADS => the fork branch. So async is the hard blocker.
- Callers (non-server): fetch-pack.c:985 (sideband_demux, in get_pack 966-1103; also reached for protocol v2 since use_sideband=2 set at 1740), send-pack.c:703 (push sideband demux), convert.c:725 (clean/smudge filter when filter command configured; only with filter.<x>.clean/smudge, e.g. git-lfs), builtin/receive-pack.c (server side only: 560,1161,2041,2319).

## Commands
WORK (start_command only: fork+exec shape): init, add, commit (hooks, editor via start_command), status, log, diff (pager -> use core.pager=cat), branch, checkout, merge, rebase, config, local clone, fetch/clone over ssh (connect.c start_command ssh child), fetch/clone/push over https (git-remote-https via start_command; curl in remote-curl in-process) -- subject to the start_command fix below.
FAIL as-is: ALL of the above that spawn a child, because fork() is absent; after the start_command fix: fetch, clone (non-local), pull (fetch-pack get_pack -> start_async demux), push (send-pack.c:703 demux only `if (use_sideband && cmds_sent)`; push over ssh/https negotiates side-band-64k from receive-pack, so yes hit), gc --auto (after commit/fetch/merge once >6700 loose objects), clean/smudge filters, git daemon, maintenance detach.
(Local file:// clone w/ upload-pack also uses fetch-pack demux.)

## Smallest source change
1. start_command: replace `fork()` (787) with `vfork()` (or posix_spawn, which libixcompat has; posix_spawn would need translating dup2 plan + chdir (posix_spawn_file_actions_addchdir_np may be missing) -> vfork is the smaller edit). Under vfork child must not leave side effects in parent: move set_die_routine/error/warn and `child_notifier=` so parent restores them after vfork returns (save before, restore after), and make the signal() reset loop restore-safe (or skip it; ixemul signal table probably per-process but shared under vfork - verify). child_die uses _exit already.
2. start_async NO_PTHREADS: cannot be vfork. Cleanest for fetch/push: drop the async demux for sideband. Option A (recommended): in fetch-pack get_pack, demux sideband in-process into a temp file / pipe is impossible without a second process, so instead spawn `git index-pack`/`unpack-objects` with a new hidden flag `--sideband-fd=N` (index-pack reads packets via sideband.c recv_sideband itself). Same for send-pack: read response with recv_sideband inline after sending (receive-pack report-status is read after the pack is fully sent; send-pack could set no async and read via a demux-reader in the main loop; originally async so remote progress prints while pack-objects pipes). Option B (generic): make start_async spawn `git --async-helper <name> <fds>` with start_command and register sideband_demux as a builtin command (data=int xd[2] only; fds inherited without cloexec). Only 2 real callers (fetch-pack, send-pack) + convert.c filter need it; convert.c: error out/config filter unused.
3. daemonize(): `return -1 / errno=ENOSYS` instead of die (or build with NO_POSIX_GOODIES-style #ifdef, setup.c:2212-2215 already has that path returning -1 gracefully!). Compile with -DNO_POSIX_GOODIES -> daemonize returns -1 without die; gc.c:692 comment then true. (Check NO_POSIX_GOODIES side effects elsewhere in git-compat-util.h before adopting.)
4. Build flags: NO_PTHREADS=1 NO_UNIX_SOCKETS=1 NO_POSIX_GOODIES=1 NO_GETTEXT NO_EXPAT/NO_CURL as needed; runtime config gc.auto=0, core.pager=cat.

## Verdict: portable with limits. Local-only workflows (init/add/commit/status/log/diff/branch/merge) work after ~15-line vfork patch in start_command. Network fetch/clone/push need an additional async replacement (sideband demux) = moderate patch (~100 lines), which is the same class of problem that blocked rsync, but git has only 2 call sites.
