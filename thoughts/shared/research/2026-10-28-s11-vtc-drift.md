# S11: VTC: drift on every rig start (RIG-START-VTC-DRIFT, MENU-STALE-RESTAGE-DRIFT)

Violated invariant: one file set defines "VTC: is current". Three lists existed: build_drift (every build/amiga file x VTC: and
UP-Term bin), install (same pairs, copies them) and the start/restage (start only warned; stale_guard's restage put the short
stage_rig.DEFAULT list into UPTERM_BIN). Only `install` made the checked set current, so the start warned on every build and the
restage left hl, mdv, rz, sz, vsh.

Level of the root cause: the file-set definition (data/list), not the check and not the message. Fix at that level:
rig.program_pairs(vtc, built) is the one list; build_drift reads it, refresh_programs copies it (atomic rename), and install,
setup (before the drift check) and stale_guard call refresh_programs + refresh_kit_shadows. No second list remains.

Test: tests/test_rig_vtc_drift_refresh.py (4 tests; all fail with the fix reverted, pass with it).
Proof: rig 4 start --max printed refreshed amarchy-gui, Apps/bin/amarchy-gui, vtcon-handler and no VTC: drift [WARN]
(log: scratchpad/start4.log). stale_guard restage not run on a live rig; covered by the unit test.
Note: vtcon-handler is refreshed from build/amiga as install does; handler/ source untouched by this change.
