# Prefs settings as Amarchy menu rows: map of what exists (2026-10-26, read-only, origin/main)

Question: every Prefs setting becomes a row in the Amarchy menu, applied at once, Prefs kept as companion, one source of truth for the settings table.

## 1. Where Prefs settings are defined

The gadget table is `pg_items[]` in prefs/prefs_ui.c:11-251 (declared prefs_ui.h:84, ids enum prefs_ui.h:20-58). It is pure data (no OS calls, host-tested by tests/test_prefs.c). Entries: id, page, kind (PGK_STRING, INTEGER, BUTTON, CYCLE, CHECK, TEXT, SWATCH; prefs_ui.h:63), label with `_` shortcut, one-line help, grid row/col, width, a PGD_* "greyed when" code (prefs_ui.h:66-73). The table is a GUI layout table, not a settings table: it holds no key name, no default, no value list. Those live elsewhere:

- Field struct `prefs_fields`, prefs/prefs_core.h:25-65 (the value of every setting).
- Parse from the upconf profile: prefs_core.c ~60-125 (the keys, defaults as `upconf_str(.., "on")`).
- Serialise: prefs_core.c:705-800 (`pc_put` / `upconf_set` per key, the values "on/off", "underline/bar", "bs/del", "show/hide" ...).
- Cycle value lists are string arrays in prefs/upprefs.c (page names at upprefs.c:137), enums in prefs_core.h:69-78; the cycle texts are NOT in prefs_ui.c.

Counted from the table itself (entries starting `{ PG_`, prefs_ui.c:11-251): 101 entries = 5 common (page switch, status, Save, Use, Cancel) + 16 palette swatches + 16 palette hex strings (the 32 are one setting, `palette`) + 48 others. By kind over all 101 entries (palette swatch/hex included): 18 CHECK, 14 CYCLE, 1 INTEGER, 16 BUTTON, and 52 more of STRING/TEXT/SWATCH kinds (10 STRING, 5 TEXT, 5 SWATCH plus the 32 palette ones, which my kind count split inconsistently: recount from the builder before using these kind numbers). The 16 buttons are actions (New, Rename, Delete, Choose, Clear, Default, Theme, Save/Use/Cancel), not settings. Per page (settings, not buttons):

- General (profile drawer `[<profile>]` in ENV:/ENVARC:up-term/up-term): font (TEXT, key `font`), fallback font (`font-fallback`), scrollback (INTEGER 1-99999 plus "No scrollback" CHECK, key `scrollback`), cursor shape (CYCLE block/underline/bar, `cursor`), cursor blinks (CHECK, `cursor-blink`), cursor colour (SWATCH + hex, `cursor-color`) and Inverse (CHECK), bell (CYCLE none/beep/visual, `bell`), bold is bright (`bold-bright`), scroll bar (`scrollbar` show/hide). Plus profile cycle and New/Rename/Delete (profile management, not a setting).
- Colors: text/background/selected text/selection colours (SWATCH+hex, keys `fg bg selection-fg selection-bg`), Theme... (BUTTON: copies a theme file's colours, `prefs_apply_theme`, themes drawer ENVARC:up-term/themes), dither (`dither`), antialias outline (`outline-antialias`), padding extends (`padding-color` extend/background), terminal type (STRING, `term`), colour mode (CYCLE, `colors`: rgb/256/16).
- Palette: 16 swatch+hex rows, one key `palette` (a single list value).
- Keyboard: meta key (CYCLE alt/amiga, `meta`), AmigaShell keys (`amiga-keys`), backspace (CYCLE bs/del), tab completion (CYCLE unix/kingcon, `completion`), KingCON when-several-match (CYCLE, `kingcon-mode` letters W L B C S, handler/kcmode.c), common part first and no beeps (CHECK, same key), .info in lists (`kingcon-info`), directory cache (`kingcon-cache`), copy on select (`copy-on-select`), wheel scrolls (`wheel` scroll/ignore).
- Advanced: screen (CYCLE workbench/own/fullscreen, `screen`), screen mode + depth (TEXT + requester, `screen-mode`, `screen-depth`), font follows aspect (`font-aspect`), program clipboard (CYCLE write/read-write/off, `program-clipboard`), highlight cat (`highlight-cat`, also the extra drawer ENV:up-term/highlight-cat, prefs_core.h:253), reflow (`reflow`), link command (STRING, `link-open`).
- Amarchy (the six Amarchy keys, all in the `[default]` profile): music/demo/hidden drawers (STRING path lists, `amarchy-music-drawers`, `amarchy-demo-drawers`, `amarchy-hide-drawers`), app icons (CYCLE generic/amiga/none, `amarchy-app-icons`), menu mode (CYCLE graphical/text/minimal, `menu-style`), menu in terminal (CYCLE text/graphical, `menu-in-terminal`), menu font (TEXT + requester, `amarchy-menu-font`).

Storage: all except the Amarchy ones are keys of one profile drawer in ENV:up-term/up-term and ENVARC:up-term/up-term (paths: prefs_core.c, `prefs_paths_upterm`; the file is upconf syntax, at most 8 profiles, a key table with a fixed size: prefs_core.c:769 notes a written "generic" would cost a slot). Not in that file: the keymap (ENV:up-term/keymap, keymap.user: no Prefs page edits it), themes drawer, the highlight-cat drawer file.

## 2. How Prefs applies a setting

There is no push. upprefs.c:842 `prefs_stage` builds the whole file text from the fields (core.c:705-800), then upprefs.c:860 `prefs_dos_save(buf, len, keep, ...)` writes it: Save = ENVARC: then ENV:, Use = ENV: only (core.c `prefs_install`: tmp, rename old to .orig, rename in; ENV: is written in place, core.h:304-311). No ARexx message, no RELOAD, nothing sent to Amarchy or the handler by upprefs (grep of prefs/ for rexx/RELOAD/PutMsg/FindPort: only the AMARCHY page keyword at upprefs.c:1876). Apply is entirely by the consumers watching or re-reading files:

- vtcon-handler windows read the ENV: file (handler/vtcon_handler.c:996 `StartNotify` on it) so a Use/Save reaches open windows through the notify.
- The Amarchy commodity (amarchy/amarchy.c:50-60, 174-195) holds `StartNotify` on ENV:up-term/keymap(.user), ENVARC: copies and Amarchy's own file (`prefs_paths_amarchy.path[0..1]`); a change calls `reload()` (amarchy.c:174: style_load, keymap reload). ARexx port AMARCHY: RELOAD, SHOW, QUIT, RUN <row>, STATUS, WIN (amarchy.c:2, 205-235).
- amarchy-gui calls `index_drawers()` (gui.c:575-586) before every index load, so drawer lists/icons/style are re-read from `amconf_load` each time.
- Per group: terminal appearance and keyboard (General, Colors, Palette, Keyboard, Advanced): file write then the handler's notify; Amarchy page: file write then Amarchy's notify / the next menu open.

## 3. How the Amarchy menu builds rows

- Rows come from the keymap: `[menu]` of dist/keymap (line 125 on) as `dotted.id = Label | action`. Parsed by config/keymap.c into `keymap.menu` (max KM_MAX_MENU 128, label KM_LABEL 32, id KM_ID 32, arg KM_ARG 80; config/keymap.h:16-21). Action kinds (keymap.h:68-79): menu:, viewer, tab:, menuid:, slash:, run:, rexx:, open:, detach:, scan:, win:.
- The level is walked by `mn_children(k, node, out, max)` (amarchy/menu_tree.c:53; MN_MAX_ITEMS 64, menu_core.h:11), giving `mn_item {row, ix, seg, label}` (menu_core.h:20). Groups come from id depth (`mn_child_node`), visibility by `mn_children_t` conditions (terminal / DOpus / WB). `row` is -1 for a group, -2 (MN_ROW_INDEX) for an app-index row, else an index into keymap.menu. Index rows (and the scan status row, gui.c:108, menu.c:112) are the precedent for synthesised rows that are not in the keymap.
- Both menus use it: the drawn menu amarchy/gui.c (modes M_LIST, input, message, viewer; gui.c:6) and the text menu amarchy/menu.c. Size is computed by walking the same tree (`mn_levels`, `mn_osd_size`, menu_geom.c).
- Row action: `lf_run` in amarchy/leaf.c:280 switches on `lf_plan(kind)` (leaf.h: LF_WINDOW, REXX, OPEN, DETACH, SCAN, VIEWER, WIN, REQUEST). A leaf needing an argument calls the UI callback `ask_value` (gui.c:1030, menu.c:63), so a value prompt (the "input" mode) exists in both menus.
- Existing settings rows (dist/keymap, [menu]): `settings.amarchy.rescan` (scan:amarchy-index), `.preferences` and `.font` both `detach:C:UP-Term-Prefs AMARCHY` (so the menu font row is only a launcher), `.edit` (run:nvim ENV:up-term/keymap), `style.theme` / `.font` / `.background` (slash:/theme /font /bg, run in a terminal window), `window.preferences` (menuid:MENU_PREFS). There is no theme picker or style row that changes a setting in the menu itself: menu_theme.c is only the palette-to-role colour table of the drawn menu.
- Current value in a row: not supported. A leaf label is the static keymap label (KM_LABEL, 32 chars) or the index entry's label; no toggle/cycle/check display, and no action kind that writes a setting. Needed for inline rows: a new row kind (like MN_ROW_INDEX) generated from a table, a value text appended to the label at build time, and a leaf kind that sets and saves directly (cycle: next value; check: toggle; string/font/colour: reuse `ask_value`, or the font/colour requesters).

## 4. Shared code and what blocks reading the table

Already shared:
- prefs/prefs_core.c/.h (fields, parse, serialise, `prefs_install`, `prefs_save_at`, `prefs_paths_*`) and prefs/prefs_dos.c are linked into upprefs, the Amarchy commodity (Makefile:692) and amarchy-index (Makefile:740); amarchy/gui.c includes prefs_core.h (gui.c:38); vtcon_handler.c includes it too. config/upconf.c + upconf_rows.c (the file syntax) are linked everywhere.
- amarchy/amconf_core.c/.h (`am_keys[AM_NKEYS]`, 9 keys with defaults, amconf_load_with/save_with, migration): the Amarchy settings already have a name+default table and their own file ENV:/ENVARC:Amarchy/prefs (prefs_paths_amarchy, prefs_core.c:843). It is the closest thing to a single settings table, and it is Amarchy-only. cxdesc.c is unrelated (keymap row to commodities input description string).
- prefs_ui.c/.h is linked only by upprefs and the host tests (Makefile:37 `PREFS_CORE`, :686); neither amarchy-gui (Makefile:731) nor amarchy-menu (Makefile:722) links it.

Findings that matter for the plan:
1. Split-state drift on origin/main: commit 4c48a1a2 moved the Amarchy keys to Amarchy's own file (amconf), but prefs_core.c:765-777 still writes them to the up-term `[default]` profile and upprefs.c has no reference to amconf (grep of prefs/ for amconf/am_keys: none). Plan item M3 in thoughts/shared/plans/2026-10-25-amarchy-own-prefs.md:243 ("Prefs Save strips legacy keys over am_keys[]") is open. Prefs and the menu therefore currently write different files for the same six settings. That must be resolved first, or the inline rows and the Prefs page diverge.
2. pg_items is layout, not semantics: no key, default, value list, apply scope. A single source of truth needs a new table (key, type, values, default, help, field offset or get/set function, apply scope) that prefs_core's parse/serialise, upprefs's gadget builder and the menu rows all walk. Today the key names and values appear in three places (parse, serialise, upprefs cycle arrays) and the table has none of them.
3. Build/size: amarchy-gui (Makefile:731) already links prefs_core.c, prefs_dos.c, upconf.c, upconf_rows.c, amconf_core.c and amconf_dos.c; so does the commodity (692) and amarchy-index (740). amarchy-menu (722, the text menu) links none of them; it would need prefs_core/dos, upconf and amconf added. prefs_ui.c is linked by none of the Amarchy programs but is pure and small (524 lines). upprefs-only code (GadTools, ASL: upprefs.c 2005 lines, prefs_asl.c) must stay out of the menus. No size budget for Amarchy (owner memory).
4. Row limits: KM_MAX_MENU 128 and MN_MAX_ITEMS 64 per level; the 48 non-palette settings fit if grouped by page (about 9-15 rows per group); a flat insert into the keymap [menu] would use 48 of 128 slots, so synthesising rows from the table (like MN_ROW_INDEX) is better than 48 keymap lines, and it keeps dist/keymap free of a second copy of the labels.
5. Several controls are not row-shaped: the 16-entry palette (32 gadgets), colour swatches (need the colour window PC_*, prefs_ui.h:52), the profile cycle and its New/Rename/Delete, Theme..., screen mode requester, font requesters. Those are the cases where the Prefs app stays the companion or the menu opens a requester.
6. Apply: a menu row that writes ENV: (Use) and ENVARC: (Save) through `prefs_save_at` triggers the existing notifies; no new IPC is needed. Writing the whole file per row means read-modify-write of the full text (prefs_stage) on every change; for Amarchy's own file that is `amconf_save_with` (small).
