# ixemul 80.1 vs our patched 48.2

Trees compared:

- **48** = pristine 48.2, `git -C ~/Code/ixemul-vtcon show 1ee186a` (extracted to the
  session scratchpad as `ix48/`).
- **ours** = `~/Code/ixemul-vtcon` HEAD `5f2d856`. The vtcon patches are `f354e6f..HEAD`, and the
  gcc 6/2.95 build commits are `1ee186a..f354e6f`.
- **80** = `scratchpad/ix80/ixemul/` (the Aminet archive's source). Readme:
  `scratchpad/ix80/ixemul-80.1-m68k.readme`.

Nothing was built and no emulator was used. "Applies" means `patch --dry-run -F3` of our per-file
diff against the 80 tree. A hunk that applied **with fuzz** is marked as needing review, because
fuzz can place a hunk in the wrong switch case.

## Verdict

**Stay on 48.2 for now. Rebase onto 80.x as a planned piece of work, not a drop-in.** 80.1
removes none of the reasons our patch set exists:

- still no fork (`misc.c:162-168`);
- ptys are still FIFO-based;
- termios is still faked from `f_ttyflags`;
- `TIOCSWINSZ` is still ignored;
- still no job control or `killpg`;
- `sendmsg`/`recvmsg` on AF_UNIX now fail with an explicit `EOPNOTSUPP`.

80 fixes two of our small bugs itself (the `unp_accept` NULL name, and the path left behind by a
failed connect) and adds `poll()`/`realpath()` as library vectors. It also rewrites exactly the
files our work lives in: `open.c`, `__close.c`, `__tioctl.c`, `__read.c`, `unp.c`, plus the
per-process select state.

It also changes one behaviour that interacts badly with our PTY:/XCON: handlers (below, R1).

**Decisive trade-off:**
- *For 80:* many robustness fixes we would otherwise never get (select, close lifetime, vfork
  message lifetime, SIGWINCH input.device handler).
- *Against 80:* about half our patch set needs rework, the SCM_RIGHTS work needs a rewrite on a new
  stream model, our handlers need a change, and the build script needs a change. All of that
  lands on an AI-assisted fork that is 5 days old, with an open "rare total system freeze" bug.

## 2. fork()

**80 has no real fork.** `library/misc.c:162-168` still sets `errno = ENOSYS; return -1`, the same as
48 `misc.c:156-162`. The `fork` vector (438) and `vfork` (446) are unchanged in `syscall.def`.

The 80 process work is all vfork lifetime hardening:

- a per-process static `u_vfork_msg_buf` (`user.h:299`);
- `p_death_msg`/`p_pending_death_msg` (`user.h:472`);
- execve clears `p_vfork_msg` before `ReplyMsg` (`execve.c` rev 1.3 note).

`mkfifo` is also still ENOSYS (`misc.c:171-175`).

## 3. TTY, PTY, termios, select, IXPIPE in 80

- **/dev/ptyXY, /dev/ttyXY:** still mapped to `FIFO:` via `/fifo/ptyXX/rweksm`, `m`/`c` suffix
  (`open.c:266-290`), with `ix_ptys[]` bookkeeping (`open.c:280-287,417`; `__close.c:171-186`).
  There is no openpty/ptsname/posix_openpt anywhere in the tree (grep).
- **termios ioctls:** still synthesised from `f_ttyflags` (TIOCGETA `__tioctl.c:376-430`). TIOCSETA
  still maps only ICANON/ECHO to `SetMode()` raw, plus CR/LF flags. That is now precomputed as
  `IXTTY_MAP_*` in `ixemul.h:122-124` (bits 0x100-0x400; our `IXTTY_VTCON` 0x40 and
  `IXTTY_VTCON_KNOWN` 0x80 are still free). No `VSUSP` (`c_cc[VSUSP] = 0`), no `VQUIT`.
- **TIOCGWINSZ:** the same ACTION_DISK_INFO -> Window/ConUnit walk, now validated with `TypeOfMem`.
  It returns **-1 whenever the chain cannot be validated** (`__tioctl.c:251-331`). The file's own
  note says a tested console got -1 there.
  - NEWS claims "sensible default terminal dimensions". **I could not confirm that**: no code in
    `library/` or `stdlib/` assigns default `ws_row`/`ws_col` (grep).
  - This does not matter to us: our packet path runs first.
- **TIOCSWINSZ:** ignored (`__tioctl.c:662`).
- **select on ptys/consoles:** reworked. There is one ACTION_WAIT_CHAR packet **per process per
  file** (`__fselect.c:170-230`, `user.h:476`). It has a 10 s timeout, and `SELCMD_CANCEL` is a
  no-op, so the packet stays out and is reused. See R1.
- **IXPIPE in execve:** `dup2_BPTR` is unchanged (`execve.c:787-801`). It still does
  `Open("IXPIPE:%x", 0x4242)` directly, with no `pr_WindowPtr = -1` around it.
  - So **an unmounted IXPIPE: still raises the "insert volume IXPIPE:" requester.** The
    `ix_no_insert_disk_requester` guard exists only in `__open.c:73-98`, and `dup2_BPTR` does not
    go through it. Same as 48.
  - `/fifo/pty` fds are still forced through IXPIPE (`execve.c:656,678,697`).
  - With our mapping the name is `PTY:XY/…`, so those fds use the DOS handle directly. That is
    unchanged from our 48.

## 4. Source and build compatibility, version, ABI

- **Compiler:** 80 targets gcc 2.95.3 (readme, "Source code").
  - It guards `__builtin_expect` for old gcc (`library/ixemul.h:93`) and `_BSD_VA_LIST_` for
    gcc < 3 (`include/machine/ansi.h`).
  - It uses `long long` in the new `strtoll`/`strtonum`/`atoll` code, which 2.95 supports.
  - **Not verified by compiling.**
- **configure / configure.in:** byte-identical to 48.
- **Build layout changed. Our `docker/build.sh` will break as written.**
  - `library/Makefile.in` now hardcodes `true_srcdir = ../../..` and `true_topdir = ../../../..`,
    because "make *runs* it inside ixemul/library/CPU/FPU/OS" (`library/Makefile.in:3-19`). That
    means an in-tree build. We configure out of tree into `build295/`, so srcdir would resolve into
    `build295/`.
  - `INCS` dropped `…/inlines/include`.
  - There is a new `intops/` directory (bswap asm, `libintops.a`) in `CPUFPUOS`
    (`Makefile.in:45`), which must be added to our explicit target list.
  - The link now also takes `glue/no-baserel/libglue.a`.
  - This is inferred from the Makefiles, not built.
- **Library version:** 80 (`version.in` `80.1,25.9.26`; prebuilt id
  `ixemul 80.1 [68020, fpu, amigaos] (25.9.26)`). `OpenLibrary("ixemul.library", <=48)` is
  satisfied.
  - ixnet.library must be the same version: `ixnet_open.c:82` refuses a mismatch. Ship both.
- **Jump table:** append-only. `syscall.def` has 631 lines in 48 (last vector 613) and 687 in 80;
  the diff is only vectors 614-656 appended (`syscall.def:632-687`). No existing slot was moved or
  removed.
  - The 80.1 "removed lseekw() vector" refers to a vector 80.0 had added. It is absent from 48,
    so it cannot affect 48-built programs.
  - 80.0 binaries that used it would break. 80.0 source was not available to check.
- **struct user:** the header says it is PRIVATE since 47.0 (`user.h`). 80 **inserts fields in
  the middle**: `u_open_name_buf[256]`, `u_path_buf[MAXPATHLEN]` (`:252-265`) and
  `u_vfork_msg_buf` (`:294-308`). So offsets from `p_zombies` onward move.
  - Programs are unaffected: `crt0.c` and `stack/` are identical to 48, stdio uses the `__sF`
    pointer (`stdio.h:137-141`), and no static lib source includes `user.h` (grep).
  - Tools that poke `struct user` directly (old ixtrace/gdb builds) would break. 80 ships its own
    ixtrace.
  - `A4_POINTERS` goes from 100 to 1000 (`user.h:143`). That array sits *before* the struct and
    its size is read at run time (`ix_settings.c:81`).
  - Cost: about 5 KB more per ixemul process (3.6 KB of a4 slots plus about 1.3 KB of buffers).
    This is an estimate from the declarations.
- **struct file** (private) gains `f_name_buf[256]`, `f_name_inline` and `f_fs_blocksize`
  (`sys/file.h:68-70`). That is +264 bytes per open file.
- **FILE, struct stat, termios.h:** unchanged.
- **Source-level header changes:**
  - `struct timespec` fields renamed `ts_sec/ts_nsec` -> `tv_sec/tv_nsec` (`sys/time.h`). This
    breaks the source of any port that uses the old names; the ABI is unchanged.
  - `sys_siglist` declaration dropped from `unistd.h`.
  - `sethostname` now takes `size_t`.
- **Conclusion:** 48.2-SDK binaries should run on 80 (append-only vectors; public structs
  unchanged). **This is not verified on the rig.**

## 5. Risks

- **R1: per-process WAIT_CHAR against our handlers (inferred, not tested).**
  - In 48 there was one outstanding select packet per `struct file`, shared across vfork children.
    In 80 each process that selects the same fd has its own ACTION_WAIT_CHAR out (`__fselect.c`).
  - Both of our handlers keep **one** waiter per side and end the older one with DOSFALSE when a
    newer one arrives: `vtcon/handler/pty_handler.c:529-532` ("a newer WAIT_CHAR ends the older
    one") and `vtcon_handler.c:2117-2118`.
  - With two selecting processes on one pty side, each re-PREPARE cancels the other. The likely
    result is spurious wakeups or a ping-pong busy loop.
  - The handlers would need a waiter list before we switch.
- **R2: known open bug.** "Rare total system freeze during process exit / window switching" in
  the SIGWINCH/input.device teardown (`BUGS`, `BUGS_SIGWINCH`), status "rare, unresolved". The
  mechanism is less exposed in 80 (installed only for processes that catch SIGWINCH), but it is
  not fixed.
- **R3: provenance and churn.**
  - The 80.x series was written with ChatGPT/Copilot/DeepSeek (readme "Authors").
  - The ChangeLog has one summary entry for all of 80.0 (2026-09-13). Detail lives only in
    per-file revision comments.
  - 80.1 had to restore licence notices dropped by the automated edits (ChangeLog 2026-09-24).
  - It is 5 days old at the time of writing.
- **R4: TIOCGWINSZ now returns -1 on consoles whose DISK_INFO chain fails `TypeOfMem`** (see
  section 3). This is a regression for other consoles (KingCON, ViNCEd, and so on), not for our
  packet path. **Not tested.**
- **R5: size.**
  - Prebuilt `ixemul020-fpu.library` is 191,800 bytes. Our 48.2+patches build
    (`build295/library/68020/68881/amigaos/ixemul.library`) is 166,104 bytes. That is +25.7 KB
    (+15%) before our patches are added.
  - Add per-process and per-file RAM growth (section 4).
- **Prebuilt binaries in the archive** (`scratchpad/ix80/Sys/`):
  - `libs/`: `ixemul000.library`, `ixemul000-notrap.library`, `ixemul000.trace`,
    `ixemul020.library`, **`ixemul020-fpu.library`** (our 68020/68881 flavour),
    `ixemul040.library`, `ixemul040-fpu.library`, `ixemul060-fpu.library`, `ixnet000.library`,
    `ixnet020.library`, `ixnet040.library`, `ixnet060.library`.
  - `l/`: `ixpipe-handler`, `ixpipe-handler_020-60`.
  - `devs/MountList.ixpipe`, `s/add_to_startup`.
  - `gg/`: bin (ixprefs, ixtrace, ixrun, ixstack, ixtimezone, zic, tzselect, ipcs, ipcrm),
    include, lib (crt0/bcrt0/gcrt0/lcrt0/mcrt0/rcrt0/scrt0.o, libc.a, libc_p.a, libb/, libb32/),
    guide, man, etc.
  - The prebuilts are useful only as an unpatched A/B reference. UP-Term needs our patches.

## 6. Recommendation

**Stay on 48.2 for the current UP-Term work. Schedule "rebase onto 80.x" as its own ledger item.**
Start it once 80.x has had a maintenance release or two, or earlier if a 48.2 bug that 80
documents as fixed bites us: select/close lifetime, the vfork message use-after-free, the
input.device handler.

Rework estimate for a rebase:

- 3 patches drop.
- 6 carry over (one line to re-anchor in `user.h`).
- 6 need hand rework: `open.c` pty block, `__close.c` select kick redone on per-process state,
  `__tioctl.c` 4 blocks, `__read.c`/`__write.c` hooks, `__vtcon_init` anchors, version string.
- 1 rewrite: SCM_RIGHTS on 80's refcounted streams.
- Plus `docker/build.sh` for the in-tree Makefile and `intops`, and a waiter list in
  `pty_handler.c`/`vtcon_handler.c` for R1.
- Then a full rig re-test of screen, tcsh job control, vsh and less.

The rework is small. The value is in 80's hardening. The cost is a re-test of everything, against a
fork whose own BUGS file lists an unresolved freeze.
