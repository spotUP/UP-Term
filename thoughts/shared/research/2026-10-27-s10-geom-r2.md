# Rig 3 drawn-menu box vs amarchy_geom (2026-10-27, session 10)

Verdict: the RIG helper (tools/rig/amarchy_geom.c + case_default) is wrong; the product is right.

Product root window (Intuition coords; wasabi lists them x2 vertically, row_scale 2): 372x206 at 134,25 on the 640x256 Workbench screen, topaz 8, pixels 22:44.
Helper as the rig runs it: 360x202 at 140,27.

Two helper input bugs (reproduced on the host with scrprobe-measured lengths):
1. `mg_screen s;` in main() (amarchy_geom.c, after `mg_screen s;` ~line 66) is never zeroed, so s.minimal is stack garbage; it came out non-zero:
   by=0, bx=0 (minimal: no border art). Product: by=2, bx=4. Effect: chrome 46 instead of 50 -> height 202 instead of 206.
   With memset(&s,0,sizeof s): root 138,25,364,206.
2. cond: helper passes only MN_COND_WB (case_default calls expected() without wb, and the helper has no MN_COND_DOPUS at all).
   Rig 3 has Directory Opus (root rows: Apps|Dopus|Settings|...), product menu_cond includes MN_COND_DOPUS, whose group has wider labels.
   With zeroed minimal + WB|DOPUS: root 134,25,372,206 n=12 = the product box exactly.

Apps level (unverified here): product keeps the 372 width by design (g->w is computed once at the opening node, gui.c:1479); the helper gives apps 360 wide because it
calls mg_width_t per node. The product apps window is 206 high like root, so ix_level_t (gui.c:1486/570, index apps merged in) yields far more rows than
mn_children_t (keymap only, helper n=3). The helper cannot predict apps rows without the index.
Not checked: my Return key on rig 3 opened Screens, not Apps (selection differs with Dopus row), so the product apps n was not read.

Rig 3 did not die this time.
Fix: memset(&s,0,sizeof s) in amarchy_geom.c; add --dopus flag (cond MN_COND_DOPUS), set by rig from the rig's Dopus presence; width of apps = root width; apps n from ENV:AMARCHY_ROWS.
