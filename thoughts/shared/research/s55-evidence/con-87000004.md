# CON 87000004 on rig 96 (3.2 full install, amarchy-flat at boot)

## Which handler is CON
- rig 96 `S:User-Startup` runs `C:UPConsole >NIL: CON ON` (after amarchy-flat BOOT). device/upconsole.c:5,207
  points the CON and RAW DosList entries' dn_SegList at L:vtcon-handler. So every CON: window opened after
  that runs vtcon-handler, and DOS names the process after the device: task "CON".
- `ami.py requesters` on rig 96 (read-only): `"Software Failure" (task CON, screen "Workbench Screen", buttons Suspend|Reboot)`.
- `rig.py wasabi guru` on rig 96: "no Guru recorded (T:lastguru absent)" (deadend requester, not a logged Guru).
  NOTE: that command printed `[REFRESH] rig 96: 1 file(s): wbrun` -- the wrapper re-copied one helper file into
  rig 96's share. No reboot; the alert was still up afterwards. Use only ami.py for read-only probes on rig 96.

## The invariant (stated in the code)
handler/vtcon_handler.c:480-483: "a DOS call made by the handler waits for its reply on our own port and would
take a queued packet for it". dos.library's DoPkt waits on pr_MsgPort; a client packet that arrives there
first is an unexpected message -> Alert(AN_AsyncPkt = 0x87000004, deadend). That is why config, splits, theme
and keymap reads run on config_worker / watch_worker processes (vtcon_handler.c:1198-1215, 1262-1330), and
dbg_flush only writes when the port is empty (vtcon_handler.c:476-477).

## The violation (cause)
handler/vtcon_handler.c:963-980 `fonts_ttf_exists()` does `Lock("FONTS:SymbolsNerdFontMono.ttf")` + UnLock
ON THE HANDLER PROCESS. Called from apply_profile (vtcon_handler.c:1539), which runs:
- at every window open: parse_spec -> apply_profile (vtcon_handler.c:1853), inside FINDINPUT/FINDOUTPUT handling
  (also for a new tab/pane in a process that already serves live clients);
- on every live config change: watch_take -> profile_switch -> apply_profile (vtcon_handler.c:2641, 2683),
  i.e. while the window's shell/programs are writing and ixemul clients have async packets in flight.
Added by 773bcc3e (2026-11-03 22:31, NERD-FALLBACK-DEFAULT); 256ad41c (2026-11-04 09:53, R3C-UD6-NERD-QMARK)
moved the call before the `if (!c->conf) return` so it now runs for EVERY window, profile or not.
rig 96's L:vtcon-handler is dated 2026-11-04 10:26, so it carries both. The Lock goes to FONTS:'s volume
handler, so the window during which a client packet can land on pr_MsgPort is a full disk round trip
(longer at boot, when the disk is busy: matches "Wait for disk activity to finish" at boot).

## Ruled out
- c6401608 (amarchy/iconpen_dos.c pr_WindowPtr=-1, branch fix/flat-boot-freeze, not main): iconpen_dos.c is not
  in HANDLER_SRC (Makefile:759); it links only into amarchy-flat/menu/gui/icons. Not on the CON process.
- amarchy-flat's hooks (sysiclass h_SubEntry, RectFill/Text patches) run on the caller's task, including CON,
  but the draw path (flat.c:211-275 clone_render/c2_draw, flat_glyph.c) makes no DOS call (grep: Lock/Open only
  in flat.c:1233-1255, the marker file, on amarchy-flat's own process). Not the cause, as far as the grep shows.

## Other DOS calls on the handler process (same bug class, not the boot trigger)
- vtcon_handler.c:750-843 kfile_lock / kfile_read / kfile_unlink (Kitty graphics t=f/t=t file reader,
  vt_set_file_reader at :3302): Lock/Examine/Open/Seek/Read/ParentDir/DeleteFile from the vt parser.
- vtcon_handler.c:4929-4934 slash_run: Open/Write/Close of a user path (a slash command that saves to a file).
- handler/clip.c:78-110 clip_write_form: Open/ExamineFH/Read of a file (check its caller's process).
- On their own processes (fine): png_worker :576, config_worker :1198, watch_worker :1262, launcher :2155,
  tab_spawner/tab_prog_script/run_async :6780-6918, complete.c (comp worker).

## Fix design
Never let the handler process make a DOS call while clients can send packets. For fonts_ttf_exists:
read the answer where the other file facts are read -- in config_worker and watch_worker (which already run
read_conf / read_active_theme off the handler's port): add `int nerd_ttf` to struct config_msg / watch_msg,
set it there with the Lock (pr_WindowPtr is already -1 in both), store it on the con (c->nerd_ttf) when
the reply/watch message is taken, and have apply_profile pass c->nerd_ttf to upconf_font_fallback instead
of calling Lock. No new process, no port swap. Regression test: a host source guard (like
tests/test_ipd_no_dos_under_list.py) that fails when any function reachable from the packet loop in
vtcon_handler.c calls Lock/Open/Examine/GetVar/... outside the listed worker entry points; plus a rig row that
opens a CON: window after UPConsole CON ON while two writers spam it and ENV:up-term/up-term is rewritten.
Then the same move for kfile_* (do the file read in a worker, reply to the parser asynchronously) and
slash_run's save (hand the write to a worker), as follow-up rows.
