# Midnight Commander port research (s56)

Kit libs today (upterm-ports/pkgs listing): ncurses, zlib, iconv, lua, perl, libarchive, xz, bzip2, file, ixcompat, plus apps incl. nnn (nnn 5.3 already ported, BSD-2-Clause, vfork patches, ncursesw), htop, tig, ncdu, vim, mutt. NOT present: glib, slang, pcre/pcre2, gettext. iconv exists.

1. GNU mc hard deps. GLib 2.x is mandatory (minimum 2.30 as of 4.8.25; PCRE2 optional as search engine alternative); screen lib slang (default) or ncurses (both supported); subshell needs a PTY and fork (bash/zsh/tcsh); VFS modules (extfs scripts) need Perl/shell, sftp/shell-link need ssh. Porting GLib 2.30+ to AmigaOS 3 = large: GMainLoop/gthread/gio need fork, pthread (stub in ixemul-vtcon), poll, plus ~950 functions. Existing ports: AmigaOS4 GLib 2.30.1 by Chris Young ("quick port", needs libffi, OS4 SDK), MorphOS GLib 2.6.6 shared lib (experimental), AROS GLib (near-complete, no timers, no fork functions), m68k GLib 2.4.4 binary from 2007 (spawning does not work, no fork). None usable for mc 4.8 unmodified (2.4/2.6 too old).
   Precedent: mc 4.6.0 was ported to AmigaOS(ixemul)/MorphOS by Pavel Fedin (2004, Aminet-era CD). Its README lists ncurses, file, perl, ssh; no GLib mentioned (unverified how it was satisfied); known gaps: no Ctrl-O subshell toggle, no mouse, key remap. So a no-subshell old mc on ixemul has shipped before. I found no evidence OS4 or MorphOS ship current mc.
2. Survey (licence, language, notes)
 - GNU mc 4.8.x: C, GPL-3, active, GLib+slang/ncurses. Large.
 - mc 4.6.0 (2004, Amiga/MorphOS port exists): C, GPL, needs glib 1.2/2.0 era; easiest GLib to emulate but still needed. Dead upstream.
 - pre-GLib mc 4.1.x: I could not verify a pre-GLib release; GLib dependency existed by 4.5/4.6 (glib 1.2 fallback). Treat as unverified; not recommended (no UTF-8, unmaintained).
 - nnn: C, BSD-2, ncurses, single pane (not mc-style), ALREADY in kit.
 - vifm 0.14.x: C, GPL-2+, ncurses (libmagic optional), genuine two-pane, active (0.14.3). Uses fork/exec for commands and pthreads for background work, needs vfork-style patching like nnn.
 - ytree 2.12 (Bregulla): C, GPL-2+, curses, XTree-style tree+file windows with a split two-panel mode, active (2026). Small, few deps; less mc-like (no mc keys/menus).
 - YtreeNova: ytree fork, alpha. cfiles: C/ncurses MIT, ranger-like, not two-panel. ncursesFM: C, GPL-3, two tabs only. xc: Python two-panel. far2l: C++ big (wx/GUI backends), not 68k fit. lf: Go, ranger/yazi: no 68k target. DOpus/Directory Opus are native Amiga dual-pane managers (not terminal).
3. Recommendation: vifm is the best mc-style candidate for 68k: only ncurses (in kit), two-pane, C. Size medium: main cost is replacing fork/pthread uses (job control, shell-out) with vfork/synchronous paths as done for nnn, plus ixemul libc gaps (fstatat etc., already being fixed) and a Vim-style key model that is not mc's F-key UI. If owner wants literal mc: GNU mc 4.8 = large (GLib port, drop subshell, drop VFS/ssh/sftp/ext2/cpio, drop mcserv, use ncurses; also needs gettext stubs, PCRE2 optional). mc 4.6.0 + a tiny GLib-1.2 subset is medium-large and gives an old UI. Fallback small option: ytree.
 Not verified: vifm fork/pthread usage (from general knowledge), mc 4.6.0 GLib handling, pre-GLib mc existence.
