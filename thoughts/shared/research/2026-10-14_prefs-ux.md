# UP-Term Prefs: what is there, what the OS offers

Scope: documentary. Sources read on the host only (no rig booted). Files:
`prefs/upprefs.c` (876 lines), `prefs/prefs_core.c/.h`, `prefs/prefs_dos.c/.h`,
reader side `handler/vtcon_handler.c` (`apply_profile`, 961-1100;
`apply_colours*`, 927-956; own screen, 2305-2385), `handler/lineedit.c:1479`,
`config/upconf.c`, `dist/README.txt` (CONFIGURATION, 102-150).
Owner request 2026-10-14: fonts via font requester, colours via picker, KingCON
style unintelligible, too many plain text inputs; addition: screen mode and
depth via the screen mode requester.

## 1. Pages and fields

Window: GadTools, one window, `WA_InnerWidth 482 x InnerHeight 244`
(`upprefs.c:63-71, 597-598`), title "UP-Term Prefs" (606). Three gadget lists
swapped by the Page cycle gadget (`show_page`, 240-253). Every gadget uses
`topaz 8` (`topaz8`, 123; `ng_TextAttr`, 407), coordinates are fixed pixel
offsets from the inner top left (`ROW(i)=20+16i`, `FIELD_X=128`, `ADV_X=184`,
64-85). Only the origin follows the screen font (`oy`, 804).

Totals (counted from `build_gadgets`, 447-584): Common 5 (Page, status text,
Save, Use, Cancel); General 21 (incl. Load/New/Delete); Colors 24 (incl. Theme
button); Advanced 9 (+3 static help texts). 54 editable gadgets on pages.
String gadgets: `N_STR = 6+4+16+3 = 29` (`upprefs.c:98`): of 29, 25 are
colour/number/name/format text that a component could replace.

Profile key semantics: an empty string field deletes the key so the handler's
built-in stands (`pc_put`, `prefs_core.c:222-229`); toggles and cycles always
write their key (`prefs_stage`, 234-290). Keys the editor does not own (`term`,
`colors`, anything hand-typed) are kept as read (`prefs_core.c:231-234`).
Limits: 8 profiles, 32 keys, name 32, value 160, file 16384 (`upconf.h:57-61`).

KingCON style mapping (from `le_kc_fncmode`, `lineedit.c:1479`): the stored
value is a letter set; an editor needs (a) one cycle for W / L / B (mutually
exclusive: W clears L and B), (b) a checkbox C ("complete common part first"),
(c) a checkbox S (silent). Reads back with `le_kc_fncmode` semantics; writing
should produce a normalised string (e.g. `LC`). B plus L together: `m` keeps
both (`W` only clears them), so L and B are not exclusive in code; the real
rules need checking before fixing the control set (open question).

### Pens for colour pickers (constraint)

- Screens of Workbench are often 4 to 16 pens (the project's dither code is
  built for that: `dither` key, `amiga_render.c:386-390`; its pen path uses
  `ObtainBestPenA`, `amiga_render.c:60-73, 172`).
- A Prefs window that wants to show an arbitrary RGB swatch has no pen of
  that colour on a small-depth Workbench. Options: `ObtainBestPenA` (nearest
  existing, approximate), or a shared pen with `ObtainPen(cm, -1, r, g, b,
  PEN_EXCLUSIVE)` (free entry, may fail), always released with
  `ReleasePen`. The colorwheel gadget itself allocates its pens
  (`WHEEL_MaxPens`) and degrades on few-colour screens.
- How Prefs/Palette handles this (unverified, no disassembly): it edits the
  Workbench's real palette, so it does not need extra pens for the preview;
  that is not the job here, UP-Term needs a preview of a colour that is not
  a Workbench pen.
- Under the dither design (W-T9) a swatch would look different from the
  window's output on few-colour screens, so the swatch is approximate by
  definition; the hex text stays the exact value.

  includes/`AslBase` (38, 39, 50) and this use.
- ASL elsewhere: `handler/complete.c` has file requester (`asl_pick`, 843),
  font requester (`font_pick`, 875) and theme (`theme_pick`, 953): the
  font tags are the ones needed here; the handler opens asl V37, Prefs V38.
  Duplicating would violate the reuse rule; a shared helper is a decision for
  the plan.
- Theme drawer logic: `prefs_theme_drawer` (`prefs_core.c`, host-tested).
- Pen/dither: `amiga_render.c` pen code (above).
- Save/Use/Cancel: `commit` (331-393): `collect` text, `prefs_validate`,
  `prefs_stage` on a copy, `prefs_dos_save` (writes ENV: and, for Save,
  ENVARC:, via temp+rename, old file kept as `up-term.orig`). Use = ENV: only.
  Cancel and the close gadget just end (764-765, 833); no confirmation if
  edits are pending. Open windows do not change (comment 11-12).
- Layout: fixed pixel table (above) plus `WA_AutoAdjust` (599); text uses
  topaz 8 regardless of the screen font; no resize gadget; labels placed
  `PLACETEXT_LEFT` so a bigger font would overlap the neighbours. Window
  height was fixed to what a PAL Workbench allows (comment 493).

  (grep of `prefs/*.c`: no match).
- Keyboard: no `&`/`_` underscore shortcuts anywhere; IDCMP is gadgets, close
  and refresh only (600-602); no `IDCMP_VANILLAKEY`, no menus. Tab moves between
  string gadgets by Intuition default only.
- Help: only the status text gadget (`set_status`, 173-180, 128 chars, two
  alternating buffers because GadTools keeps the pointer) and three static
  text hints on Colors/Advanced. GadTools 3.1 has no tooltips. Places to show
  context help: the status line (already there) updated on `IDCMP_GADGETDOWN`/

  or an AmigaGuide file via `OpenAmigaGuideAsync` (amigaguide.library is in
  the 3.1 image `Libs/`, not used by Prefs).
- Status for invalid input exists only for palette, selected text, selection

## 4. Screen mode requester (owner addition)

asl.library `ASL_ScreenModeRequest` (V38, so available on 3.1 and 3.2; same
`AslBase` the app already opens at 38). Result struct `ScreenModeRequester`
(`asl.h:301-325`): `sm_DisplayID`, `sm_DisplayWidth`, `sm_DisplayHeight`,
`sm_DisplayDepth`, `sm_OverscanType`, `sm_AutoScroll`.

Tags (`Include_H/libraries/asl.h:344-423`, `Autodocs/asl.doc:700-840`):

| Tag | Role |
|---|---|
| `ASLSM_Window` / `ASLSM_Screen` / `ASLSM_PubScreenName` | parent |
| `ASLSM_TitleText`, `ASLSM_PositiveText`, `ASLSM_NegativeText` | texts |
| `ASLSM_InitialDisplayID` | preselect mode (from the current `screen-mode` hex) |
| `ASLSM_InitialDisplayDepth` (UWORD, default 2) | preselect depth |
| `ASLSM_InitialDisplayWidth/Height`, `ASLSM_InitialOverscanType`, `ASLSM_InitialAutoScroll` | other initial values |
| `ASLSM_DoDepth` (default FALSE) | show the Colors slider (depth) |
| `ASLSM_DoWidth`, `ASLSM_DoHeight` (default FALSE) | numeric size gadgets |
| `ASLSM_DoOverscanType`, `ASLSM_DoAutoScroll` | overscan cycle, autoscroll checkbox |
| `ASLSM_PropertyFlags`, `ASLSM_PropertyMask` | mode filter: shown when `(DisplayInfo.PropertyFlags & mask) == (flags & mask)`; default both `DIPF_IS_WB`, i.e. only Workbench-capable modes (`asl.doc:794-815`; `DIPF_*` in `graphics/displayinfo.h:79-100`) |
| `ASLSM_MinWidth/MaxWidth/MinHeight/MaxHeight`, `ASLSM_MinDepth/MaxDepth` (MaxDepth default 24) | range filters |
| `ASLSM_FilterFunc`, `ASLSM_CustomSMList` | hook / extra modes |

What it replaces and how the profile stores it:
- Replaces the Screen mode string (549) and the Screen depth string (554):
  `sm_DisplayID` -> `screen-mode = 0x<hex>` (format as `0x%lx`; the reader
  accepts with or without `0x`, `vtcon_handler.c:1002-1013`),
  `sm_DisplayDepth` -> `screen-depth = n`. With `ASLSM_MinDepth 4` and
  `ASLSM_MaxDepth 8` the requester agrees with the handler's clamp (2349-2354);
  its default max 24 would offer depths the handler silently cuts.
- Do not enable `DoWidth/DoHeight/DoOverscanType/DoAutoScroll` unless the
  handler is changed: the handler ignores those (fixed at `STDSCREENWIDTH`,
  `STDSCREENHEIGHT`, `OSCAN_TEXT`, autoscroll on; 2370-2373), the profile has no
  keys for them. A gadget that moves nothing breaks the "every knob moves
  the output" rule (REACHABILITY_PROTOCOL). Adding size/overscan would be new
  profile keys plus a handler change plus a reachability test: a product
  decision, not a UI one.
- "Blank = the Workbench's mode / default depth" needs a "Workbench's" /
  "Automatic" choice beside the requester button (the requester always
  returns a concrete mode); depth blank has handler semantics (4/5/8 by mode
  kind, 2325-2347) that the requester's depth cannot express.
- The Screen cycle (Workbench/Own/Full) decides whether mode/depth matter at
  all; the fields could be disabled (`GA_Disabled`) when Workbench is picked
  (nothing is disabled today).
- Filtering: default `DIPF_IS_WB` hides non-WB modes; keep it or clear it
  deliberately: the handler opens its own screen with `SA_DisplayID` so any
  mode openable by `OpenScreenTagList` works (unverified for P96 modes beyond
  the note at 2343-2346).

## 6. Ranking of the worst fields (judgement, from section 1)

1. KingCON style: opaque letters, hidden rules, inert unless KingCON completion.
2. Screen mode: hex display ID with no way to find a valid one; garbage accepted.
3. The 20 colour hex fields (palette, fg, bg, cursor, selection): no swatch, no
   picker; only 3 of them validated.
4. Font and Fallback font: free text `NAME:SIZE` / `.otag` basename; the app has
   the font requester code in `complete.c`.
5. Scrollback (non-numeric silently means none) and Screen depth (no range).
