## 1. pty-handler (`handler/pty_handler.c`, 882 lines)

**Names.** `PTY:<id>/m` is the master, `PTY:<id>/s` a slave (header comment :1-36). `parse_name` (:447-485): takes the text after the colon, the last `/` splits id from side; side must be exactly one char `m`/`s`, case-insensitive; id 1-15 chars (`ID_MAX 16`, :107), compared case-insensitively (`id_eq` :149). `"*"` and `CONSOLE:` return 0 = "the port's own pair" (:455-456).

**Open** (`do_open`, :487-538), for ACTION_FINDINPUT/OUTPUT/UPDATE (:611-615):
- Master: id already present -> `ERROR_OBJECT_IN_USE` (:507-510), the way a program scans ids; else `new_pair` (:391-411). Handle gets `fh_Arg1 = pair | 1` (bit 0 = master, `EP_PAIR/EP_MASTER` :125-126), `fh_Type = &p->mport` (:521-523), `fh_Port = DOSTRUE` (interactive, :519).
- Slave: pair must exist and have a master (`hung_up`, :512). Handle gets `fh_Arg1 = pair`, `fh_Type = &p->sport` (:536-538). The first slave opener becomes the break target via `brk_open(&p->brk, d->dp_Port)` (:531-533).
- `"*"` only works on a slave port (another slave of the same pair, :494-499).
- Each side has its own MsgPort in the pair (`struct pair` :96-118, `init_port` :382-389: all ports share the handler's one signal bit). ACTION_WAIT_CHAR and ACTION_SCREEN_MODE carry no handle, so the arriving port says whose they are (`packet` :626-635 -> `by_port` :544-575).
- A Shell started on a slave takes `fh_Type` as `pr_ConsoleTask` so `Open("*")` and ACTION_DISK_INFO reach the pair (upgetty does this, `device/upgetty.c:174`).

**Where the ldisc plugs in.** `ldisc ld` is a member of `pair` (:104); `new_pair` sets its callbacks `ld.echo = ld_echo_cb` (:399, defined :226-229, appends to the master's out buffer) and `ld.signal = ld_signal_cb` (:400, defined :231-241, INT/QUIT/TSTP -> `brk_send` CTRL_C/E/F), then `ld_init` (:402). Master ACTION_WRITE -> `ld_input` (:686-690). Slave ACTION_READ -> queue then `slave_reads` -> `ld_read_action` + `ld_read` (:342-368). Slave ACTION_WRITE -> `slave_writes` (:250-296) -> `ld_output` (OPOST) into `out[OUT_MAX=4096]` (:104-118, :270-280); the writer blocks when the master does not drain it, and ^S (`ld.stopped`) pauses it (:262). Master ACTION_READ -> `master_reads` (:317-340) drains `out`; EOF (0 bytes) when a slave was opened and all closed (`slave_ever`, :325-327). `service()` (:370-379) loops the three until nothing moves.
- The ldisc itself is `tty/ldisc.c` (451 lines) + `tty/ldisc.h` (164): portable C89, no OS calls, host-tested (`tests/test_ldisc.c`). API in `ldisc.h`: `ld_defaults`, `ld_make_raw` (ldisc.c:30), `ld_init`, `ld_set` (:319), `ld_input` (:276), `ld_read`, `ld_read_action` (:343), `ld_input_pending`, `ld_nread`, `ld_output`. `vt_termios` is ixemul 48.2's `struct termios` byte for byte and is the wire format of TCGETA/TCSETA (ldisc.h header comment).
- Same ldisc is linked into XCON: (vtcon-handler) and pty-handler: Makefile :653-662 builds `pty-handler` from `pty_handler.c brk.c waitset.c tty/ldisc.c`, `vlink ... -nostdlib -s`, no C startup (`handler_entry` first in the hunk, :62-66). Size 12092 bytes (`build/amiga/pty-handler`, 5 Oct build).

**Mount and Startup string.** `dist/PTY` (4 lines of DOSDriver: `Handler = L:pty-handler`, `Priority = 5`, `StackSize = 8000`, `GlobVec = -1`; no `Startup =`, no `Device`). The handler does NOT read a Startup string: from the startup packet it uses only `dp_Arg3` (the DeviceNode BPTR) and replies; `node->dn_Task = main_port` (:828-832). `grep -n 'Startup\|dn_Startup' handler/*.c` found only unrelated comments in `complete.c:370-371`. (`dp_Arg2`, the startup BSTR, is ignored.)
- Lifetime: a single process serves every pair; with no pair left (after at least one existed) it clears `dn_Task` under Forbid and returns (:863-880); DOS restarts the same code at the next Open (comment :122-124 "Per start of the handler"; statics are re-initialised in `handler_main` :800-806).

**Event loop** (`handler_main` :793-880). `Wait(1<<main_port->mp_SigBit | 1<<timer_port->mp_SigBit)` (:840). Then: drain the handler's own port (:841-842), then each pair's master and slave ports one packet at a time, restarting the list scan because a packet may free the pair (:843-856), then `timers_done()` (:769-791). Only two signal sources: the packet signal (shared by all ports) and the timer port. No serial or other IORequest source exists in the loop today.
- `handler/waitset.c` (85 lines) / `waitset.h` (52): the ACTION_WAIT_CHAR waiter set per side (`WS_MAX 8`), one per task, each with a deadline; `ws_drop_task`, `ws_add`, `ws_take`, `ws_expired`, `ws_next` (waitset.h:27-48). Driven in `by_port` (:552-574) and the per-side timer (`rearm` :299-308, `expire` :760-767, `timers_done` :769-791). Three timers per pair: master WAIT_CHAR, slave WAIT_CHAR, VTIME (:114-117, :405-407).

**Window size and signals.**
- Size: `pair.ws` defaults 24 x 80 (:403-404). `ACTION_VTCON_SWINSZ` (:731-747): copies the winsize and answers in `dp_Res2` the slave's break target (a `struct Task *`) when the size changed, so the caller (ixemul, patched) can raise SIGWINCH; 0 = unchanged. `ACTION_VTCON_GWINSZ` (:723-730) copies it out. `stty rows/cols` in the far terminal is therefore not implemented by the handler; the master owner sets the size (upgetty sets it once at start, `upgetty.c:135-143`, :234).
- Signals: ISIG keys -> `ld_signal_cb` -> `brk_send(&p->brk, SIGBREAKF_CTRL_C/E/F)` (:231-241). `handler/brk.c` (`brk.h:25-37`): target is the last ACTION_CHANGE_SIGNAL port while its process lives, else the opener (`brk_open`). ACTION_CHANGE_SIGNAL on a slave -> `brk_change` (:700-705). A patched ixemul turns CTRL_C/E/F into SIGINT/SIGQUIT/SIGTSTP (header :21-24; `vtcon_packets.h` tail).

**Packets served** (switch in `packet`, :605-758):
- By port, no handle: ACTION_WAIT_CHAR, ACTION_SCREEN_MODE (:626-635). `SetMode(fh, 1)` -> `set_mode(raw)` -> `ld_make_raw` = cfmakeraw, remembering the cooked termios; `SetMode(fh, 0)` restores it (:583-603; `by_port` :545-551). WAIT_CHAR: a newer one of the same task ends the older (:562-565); ready -> TRUE, timeout <= 0 -> poll FALSE, else waits in the set.
- Handle-less: ACTION_IS_FILESYSTEM -> DOSFALSE (:616-618); ACTION_DISK_INFO -> zeroed InfoData with `id_DiskType = 'CON\0'`, no window (`id_VolumeNode` 0) (:619-625).
- By handle (`dp_Arg1` = fh_Arg1): ACTION_VTCON_NREAD (:646-648, FIONREAD), ACTION_END (:649-669, last-handle close ends pending reads with 0 and frees the pair), ACTION_READ (:670-685, queues up to `Q=16`), ACTION_WRITE (:686-699), ACTION_CHANGE_SIGNAL (:700-705), ACTION_VTCON_TCGETA (:706-713, Res2 = 1 "termios mode"), ACTION_VTCON_TCSETA (:714-722), GWINSZ, SWINSZ, ACTION_FLUSH (:748-750). Everything else: DOSFALSE / ERROR_ACTION_NOT_KNOWN (:751-754). Not implemented: ACTION_VTCON_HOLD (job control), ACTION_VTCON_WORDS, ACTION_VTCON_COMMAND (XCON-only, `vtcon_packets.h:13-60`); vsh sends HOLD and ignores a refusal (`shell/vsh.c:182-188`). Not served: ACTION_SEEK, ACTION_EXAMINE_FH, ACTION_PARENT_FH, ACTION_COPY_DIR_FH, ACTION_CHANGE_MODE etc. (none in the switch; searched `case ACTION_` in the file).
- Private packet numbers: `handler/vtcon_packets.h` (ACTION_VTCON_WORDS 0x7654 ... COMMAND 0x765B).

**Master-side behaviour a serial bridge relies on.** Master reads wake when `out` has bytes (`master_reads` :317-340, with the WAIT_CHAR wake at :337-338); there is no flow control from the master back to the ldisc input (ACTION_WRITE on the master always replies at once, `ld_input` drops excess; `LD_QUEUE 4096`, `LD_LINE 1024`, ldisc.h). Echo is lost when `out` is full (`out_append` :218-224, "as on Unix").

## 2. upgetty (`device/upgetty.c`, 324 lines)

- **Size/deps.** `build/amiga/upgetty` 10632 bytes. Built with the plain vbcc startup: `$(VC) -dontwarn=153 -o $@ device/upgetty.c` (Makefile :521-524). No ixemul. Uses `stdio` `printf`/`sprintf` (vbcc's libvc), `ReadArgs`, `serial.device`, `dostags.h` (`CreateNewProcTags`), `SetVar`. Needs `handler/vtcon_packets.h` only.
- **Template** `UNIT/K/N,BAUD/K/N,ROWS/K/N,COLS/K/N,TERM/K,SHELL/K,DEVICE/K,LOOP/S,RTSCTS/S` (:188). Defaults: unit 0, 19200, 24 x 80, TERM `xterm-256color`, SHELL `C:vsh`, DEVICE `serial.device` (:206-211; header :9-17).
- **Serial open / parameters** (:211-227): two IOExtSer (`rd`, `wr`) on one port; `OpenDevice(dev, unit, rd)` (:214); then `io_Baud = baud`, `io_ReadLen = io_WriteLen = 8`, `io_StopBits = 1`, `io_SerFlags = SERF_XDISABLED | SERF_RAD_BOOGIE | (RTSCTS ? SERF_7WIRE : 0)` (:221-224), `SDCMD_SETPARAMS` via DoIO (:225-226); `*g.wr = *g.rd` copies the settings (:227). So 8N1, XON/XOFF disabled, RTS/CTS only on request (ledger T4: with SERF_7WIRE nothing left FS-UAE's port, `thoughts/.../2026-09-28-vtcon.md:177-181`).
- **Copy loop** (:243-296), one `Wait` on serial reply port, master-packet reply port, Ctrl-C/E (:244):
  - serial -> master: one pending 1-byte `CMD_READ` (`serial_read` :88-95); when it completes, `SDCMD_QUERY` (:259) then one more `CMD_READ` for the buffered bytes (:262-269); the lot is `Write(g.master, ...)` (:273), which is the PTY master's ACTION_WRITE -> `ld_input`. Then `serial_read` again (:275).
  - master -> serial: one pending raw ACTION_READ packet to the master via `PutMsg(fh->fh_Type, ...)` on the getty's own `StandardPacket` and reply port `pport` (`master_read` :106-119; asynchronous because `Read()` would block the pump); on reply `n > 0` -> `serial_write` (`DoIO` CMD_WRITE, :97-104) then `master_read` again (:279-283). Reply with n <= 0 = every slave closed.
- **Shell start** (`start_shell` :150-184): opens `PTY:<id>/s` twice (in, out), `LoadSeg(shell)`, `SetVar("TERM", term, GVF_LOCAL_ONLY)` (:168), then `CreateNewProcTags(NP_Seglist, NP_Input=in, NP_Output=out, NP_CloseInput/Output, NP_Cli, NP_CopyVars, NP_StackSize 16000, NP_ConsoleTask=slave fh_Type, NP_Arguments "\n")` (:171-175), then ACTION_CHANGE_SIGNAL naming the shell process as the break target so the terminal's Ctrl-C never reaches upgetty (:181; comment :143-149). Pair id: first free `PTY:ser<N>/m`, N 0..63 (`open_master` :121-133). Size set once by ACTION_VTCON_SWINSZ on the master (`set_size` :135-143; :234, :288).
- **LOOP**: when the master read returns <= 0 and LOOP is set: close master, `open_master`, `set_size`, `start_shell`, `master_read` (:284-292); else end (:293-295). Ctrl-C (Break) to upgetty ends it (:247-250). Cleanup closes the master first so a pending master read returns (:297-303).
- **Seam.** The serial half is self-contained: `serial_read`/`serial_write` (:88-104), device open + SETPARAMS (:211-227), the two directions of the pump (:252-283). It touches the PTY side only through `Write(g.master)` (:273), the master read packet (:106-119), and `set_size` (:135). The process/CLI half is `open_master` (:121), `start_shell` (:150), the LOOP restart (:284-292) and size defaults. They interleave only in the single `Wait` loop (:243-296) and the shared `getty` struct (:41-52). Debug trace: `LG()` in-memory log (:61-86), the release build still evaluates its argument (:81-85).
- Install: SERIAL option writes `Run >NIL: C:upgetty LOOP` into S:User-Startup between marked lines (`dist/install.dos:325-341`; Uninstall removes it). README "SERIAL LOGIN" `dist/README.txt:369-393`.

## 5. vsh (`shell/vsh.c`, 1550 lines, plus `shell/sh_exec.c`, `sh_expand.c`, `sh_parse.c`, `config/termurl.c`)

- **Arguments** (`vsh_main` :1237; parse :1313-1331): `vsh -c COMMAND [NAME [ARG...]]` sets `command`, arg0 = NAME (:1318-1322); `vsh FILE [ARG...]` (first arg not starting with `-`) sets `script`, arg0 = FILE (:1323-1326); `ctx.flags = "i"` (interactive) only when neither and `IsInteractive(Input())` (:1330). A script is run as `source "$0"` (:1352-1354), the file opened by `os_open` -> `Open(path, MODE_OLDFILE)` (:224-252). So today `vsh AUX:` opens AUX: as a script (ledger :164-165), reading it line by line with commands run, output to the starting window.
- **Console.** `sh.io.in/out/err = Input()/Output()/Output()` (:1275-1277). Prompt loop: `if (IsInteractive(Input())) prompt(...)` then `FGets(Input(), line, 1024)` (:1366-1368): cooked, line at a time; `Flush(Input())` first to drop the argument line (:1335). termios/job control go through packets to `fh->fh_Type` of `Input()`: `console_termios` TCGETA (:168-175), `console_hold` HOLD (:178-184), `console_set_termios` TCSETA (:186-191), `SetMode(Input(), 0)` (:756, :816). At startup TCGETA decides whether it is a vtcon-class console: if it answers, TERM defaults to `vtcon` unless a local `TERM` exists, and TERMCAP is set (:1290-1305). A PTY slave answers all of this (pty_handler :706-722). External commands get their own handle on the console with `Open("*")` (:656-670, :686-690), which needs the process's `pr_ConsoleTask` set to the console's port.
- **Under NewShell today**: README says `Shell: NewShell "XCON:0/20/640/300/UP-Term/CLOSE", then vsh.` (`dist/README.txt:272`); `vsh` is typed in an XCON: window (:274). Started from Workbench (argc == 0) `wb_start` (:1458-1527) opens an XCON: window and runs `SystemTags(cmd, SYS_Input win, SYS_Output out, SYS_UserShell TRUE, SYS_Asynch, NP_ConsoleTask ...)` (:1507-1509). vsh's own use of `SYS_UserShell` is only for the Shells it starts for scripts/Resident commands (:158, :380-381, :1507). The upgetty path starts vsh via `CreateNewProcTags(NP_Seglist ...)` (`upgetty.c:171`).
- **Purity / re-entrancy: vsh is not pure.** Writable static data in vsh.c: `pipe_tab[32]` (:101), `pipes` (:267), `words_sent[3][2048]` and `words_sent_len` (:1097-1098), `term_marks`, `command_ran` (:1130-1131), `swap` StackSwapStruct, `g_argc`, `g_rc`, `g_argv` (:1408-1410), `vsh_entry_ptr` (:1423), `static sh_shell sh` and `static vproc vp` inside `vsh_main` (:1239, :1243), `IconBase` global (:1425). In sh_expand.c: `static char num[24]` (:344). `grep` of sh_exec.c, sh_parse.c, termurl.c found no file-level writable statics (regex search; not a full audit). Build: `vc +tools/vbcc-aos68k.cfg ... -cpu=68020 -O2` (`Makefile:228`) with `$(VSH_SRC)` = vsh.c sh_exec.c sh_expand.c sh_parse.c termurl.c (:291-294); link line in the cfg: `vlink -bamigahunk -x -Bstatic -Cvbcc -nostdlib -mrel startup.o ... -lvc` (`tools/vbcc-aos68k.cfg`), i.e. ordinary absolute-hunk executable with vbcc's `startup.o`, no `-fbaserel`/`-resident`. Output `build/amiga/vsh` 67416 bytes. A second instance per process works only because each CLI's hunks are freshly loaded; one shared seglist (Resident, pure) would share `pipe_tab`, `words_sent`, `term_marks`. vsh already runs on its own 64 KB stack (swap at :1529-1550) because the interpreter recurses.
- **Residents.** vsh reads the resident list for commands only: `resolve()` calls `FindSegment(name, 0, 0)` then `FindSegment(name, 0, 1)` (:485-487) and runs them with `RunCommand` or SystemTags (:372-381). vsh does not call `AddSegment`/`Resident` for itself (`grep -n 'AddSegment\|FindSegment' shell/vsh.c`: only :485-487).
- Other Shell-replacement-relevant: `vshrc` read from ENV:vsh/vshrc then $HOME/.vshrc (:1337-1349); `ENV`-style locals imported (:1268-1272); GG:bin/sh = vsh for ixemul's `system()` (`dist/README.txt` "THE SHELL FOR UNIX PROGRAMS" from :~395).
