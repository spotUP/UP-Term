## 1. upkg-ask and upkg-ui
- upkg-ask is NOT the ncurses program. It is a POSIX shell script, V/dist/upkg-ask (120 lines), run under vsh (= /bin/sh on the Amiga). It reads a questions file (`key|type|prompt|default|choices`, dist/upkg-ask:1-20), writes `KEY='value'` assignments, and calls `upkg-ui` per question (dist/upkg-ask:34-37 ask_ui, :90-110 the case on ui.string/yesno/choice). Modes: ui (stdin is a tty and upkg-ui on PATH), plain prompts, defaults (no tty) (:39-45).
- The ncurses program is upkg-ui: C, own code, P/pkgs/upkg-ui/src/upkg-ui.c (583 lines) + chrome.c/chrome.h (pure line builders, no curses, 249+66 lines) + test_chrome.c. Recipe P/pkgs/upkg-ui/recipe.mk: deps ixcompat + ncurses (ncursesw, static libncursesw.a), stack 65536, no fork, host build also runs test_chrome (recipe.mk:16-24).
- Widgets: exactly three, one per process: --inputbox, --yesno, --menu (parse upkg-ui.c:462-500; dialog-compatible call shape `--title T --backtitle B [--default-item X] [--defaultno] [--no-items] WIDGET PROMPT H W [MH tag item...]`). Result on STDERR, exit 0 ok / 1 cancel / 255 Escape (upkg-ui.c:413-450 run(), :555-583 main; Escape = c==27 at :437). No list-with-extra-keys: the menu (key_menu :385-410) handles Up/Down/Home/End/PgUp/PgDn, Enter, and first-letter jump (:405); selection is the msel/mtop state, drawn magenta/black via a_sel (theme: door SDK chrome, "Uprough Neon (muted)", double cyan border, masthead rail animated by a 1 s timeout(1000) tick, :413-430). Footer hints are H_MENU (:290) = Up/Down Move, Enter Accept, Escape Cancel.
- Consequence (my inference, unconfirmed by prototype): `browse` cannot be built from the existing --menu: the menu returns on Enter only and ignores i/r/u (returns 0 only on KEY_ENTER, :396; other letters only jump). A browse view needs either a new widget (e.g. `--browse`) in upkg-ui.c that reuses chrome.c, draw_menu/menu_room and the key loop, with extra hotkeys returning distinct exit codes or a key on stderr; or a shell loop that re-runs `upkg-ui --menu` and then asks what to do (Enter = info only).
- Shipping: V/Makefile:1082-1083 copies dist/upkg-ask to $(KIT)/Files/userland/bin/upkg-ask (-> UP-Term:bin). upkg-ui comes from the ports kit (build/kit/userland, P pkgs/upkg-ui BINS bin/upkg-ui). upkg-ask called from postinst written by V/tools/pkgs.py:155-170 (`vsh UP-Term:bin/upkg-ask STAGE/Files/questions STAGE/answers NAME`); keys parsed at pkgs.py:260.
- Host tests: V/tests/test_upkg_ask.py (206 lines; fake upkg-ui on PATH logs argv, reads "RC VALUE"; one case runs real host build P/build/host/upkg-ui/upkg-ui on a pty with keys; each case under /bin/sh and V/build/vsh_host). Wired in V/Makefile:115 (`make test`, ONLY=installer|packages). V/tests/test_dist_ipk.py:112-126 checks the postinst text. Ports side: P/Makefile:28-30 builds/runs test_chrome; upkg-ui check files P/pkgs/upkg-ui/check/{cases,keys/{input,menu,yesno},tty}. cases format is `name<TAB>command` e.g. `usage<TAB>upkg-ui 2>&1 | sed -n 1p`.
- Rig test: V/tools/rig/upkg_ask_rig.py (192 lines; passes A string, B plain fallback, C three kinds; `--only C`; sends keys to an UP-Term window on a rig; needs `rig.py start --max`).

## 3. opkg output formats (OS = patched source; stock formats unchanged by patches except wrapping)
- `list` / `list-installed` use print_pkg, OS/libopkg/opkg_cmd.c:54-80: `NAME - VERSION - DESCRIPTION` (sprintf_alloc "%s - %s" then "%s - %s\n"), or `NAME - VERSION\n` without description; with `--size`: `NAME - VERSION - SIZE - DESC` (size = installed_size if installed/unpacked, else size) (:63-70). list is opkg_list_find_cmd :538-562 (glob arg); list-installed :643-667 (sorted by name, fnmatch). Wrapped to console width with hanging indent when stdout is a tty, plain when piped (upkg_wrap_puts :80, patch 0009).
- `list-upgradable`: OS/libopkg/solvers/internal/opkg_action.c:249-266, `printf("%s - %s - %s\n", name, old_version, new_version)`. Needs the lists (`upkg update`) loaded.
- `info [pattern]` / `status`: opkg_info_status_cmd opkg_cmd.c:709-760 -> pkg_formatted_info OS/libopkg/pkg.c:875-: Debian control fields in order Package, Version, Depends, Pre-Depends, Recommends, Suggests, Provides, Replaces, Conflicts, Status, Section, Essential, Architecture, Maintainer, MD5sum, Size, Filename, Conffiles, Source, Description, Installed-Size, Installed-Time, Tags; `Field: value` lines, blank line between packages. `info` = available (installed ones show Status `install ok installed`); `status` = installed only. `--fields` filter via fields_filter.
- A package that is both listed and installed: `list` prints it once (available), so "installed?" needs a join with `list-installed` output (inference, unverified on a real feed).
- Existing parsers: NONE found. grep -e list-upgradable -e list-installed over V and P (excluding .claude/ and patches/) hits only docs/todos and P/pkgs/opkg/check/help_piped.txt (help text). V/tools/pkgs.py has `index` (writes upkg-index.txt for the older upkg) and parses Files/questions, but no opkg output. Reusable machinery is libopkg itself (opkg_list_packages API OS/libopkg/opkg.c:574 opkg_list_upgradable_packages with callback, header libopkg/opkg.h:68; recipe has -DWITH_LIBOPKG_API=OFF, recipe.mk, so it is not built -- a browse inside upkg would call internals instead).

## 4. install/remove on the Amiga today (child processes, prompts)
- Maintainer scripts: pkg_run_script OS/libopkg/pkg.c:1335-1390: setenv PKG_ROOT, builds `"<script> <args>"`, `xsystem({"/bin/sh","-c",cmd})`. xsystem OS/libopkg/xsystem.c:39-: vfork + exec, waitpid. stdin/stdout/stderr are INHERITED (no pipes): the child writes straight to the same console. IXSTACK=262144 for children (patch 0014); upkg itself __stack 262144 (recipe.mk:37-38).
- Add-on postinst (V/tools/pkgs.py:155-170): `vsh UP-Term:bin/upkg-ask ...` from the postinst script, i.e. grandchild of upkg, with the console's stdin tty; upkg-ui does initscr()/endwin() itself (upkg-ui.c:557-:575).
- So yes: a browse UI that runs `upkg install X` as a child must leave curses mode first (endwin()/def_prog_mode + endwin, then reset_prog_mode/refresh after), because the postinst's upkg-ui needs the terminal in cooked/normal state and prints plain text (download progress, script output) on the same console. If browse runs in the same process as opkg install (option a), the install log also needs a "press a key" pause before redrawing. Nested curses (child initscr while parent holds raw mode) is unproven on ixemul/UP-Term -- UNVERIFIED, would need a rig test. Note todos.md:1048 open item: an up-claude question once showed as a plain `[so_remote]:` prompt, not the box (CON: window from ami.py long vs fallback) -- cause unknown.
- Owner wants upkg runs inside the UP-Term terminal, typed into it, not via `ami.py long` (todos.md:1049); memory: A1200 long runs use `ami.py long`, rigs run as 060 (`rig.py start --max`).

## 6. Test conventions
- Host test for a V script/tool: V/tests/test_*.py (unittest, python3), listed in V/Makefile `test` target (:115 for test_upkg_ask under installer|packages ONLY filter); build/vsh_host used to run scripts under vsh.
- opkg patches: P/pkgs/opkg/check/*.sh, each `sh check/X.sh <host upkg>` (arg = build/host/opkg/inst/bin/upkg); run by mk/common.mk:165 loop over pkgs/<p>/check/*.sh with opkg_CHECK_SH_BIN (recipe.mk:34). Style: `set -eu`, mktemp dir + trap, `[OK]`/`[FAIL]` lines (check/help_flag.sh). C shims for libc faults: check/ffs_names.c, statvfs_fail.c, wrap_split.c. check/ipk.py builds a test .ipk; check/cases and help_piped.txt are fixed-output expectations. Each patch's recipe.mk comment names its check and the check must fail with the patch reverted.
- upkg-ui: pure builders in chrome.c with test_chrome.c (cc, run in host build, recipe.mk:20); check/cases (cmd lines), check/keys/{input,menu,yesno} (key scripts, format not read -- unconfirmed), check/tty; real-binary pty test lives in V/tests/test_upkg_ask.py.
- Rig: V/tools/rig/upkg_ask_rig.py (pattern for a browse rig: copy binaries to UP-Term:bin, send keys to an UP-Term window, check files + screenshots via report.md); also tools/rig/paths.py, ami.py (keys are HEX: Return = `key 44`).
- Reachability protocol (global CLAUDE.md): one test through the real entry point (`upkg browse` on the rig) with a sentinel; widget behaviour tested at chrome.c/pure-function level.
