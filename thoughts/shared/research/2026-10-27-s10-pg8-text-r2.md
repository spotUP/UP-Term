## Hangup text leak (owner screenshot 23:07, ~/Desktop/upterm-shots/rig4-hangup-leak.png)
Exact text: `Hangup - VTCX:Apps/bin/amarchy-menu ser` then `ve` on the next line (i.e. "Hangup - VTCX:Apps/bin/amarchy-menu serve"), in the 'menuhost' window (0,20 600x200): it starts at the right edge of the Packages row (after the `>`, shown as "Ha") and wraps onto the two rows below the list.
Writer: the ixemul runtime inside the warm server process `amarchy-menu serve` (menu.c serve(), line 609) printing its default SIGHUP message "Hangup - <program>" to stderr, which serve_one binds to the XCON window (menu.c:563-575). menu.c has no SIGHUP handler (only SIGINT, lines 633 and 674). The SIGHUP comes from the console hang-up break (CTRL_D) that a closing XCON window sends; commit 9581521d (vsh forwards CTRL_D) is the vsh side. Which window close sent it is unverified (rig script closes vsh windows via vshwin.close_vsh('menuhost') etc.). Source grep for "Hangup" in vtcon shell/tty/proc/handler/amarchy found nothing, so the string is from the ixemul library (not in this repo): unverified there.
A pkg_text verdict taken with the text on screen: unverified; the row parser (tx_rows) only keeps lines matching `|?  \S`, so a trailing "Hangup" fragment on the Packages row would be ignored; the grey-row abort in r2 may be related. Product bug (not fixed): the server should ignore/handle SIGHUP (signal(SIGHUP, SIG_IGN) or close the session) instead of printing into the menu.
