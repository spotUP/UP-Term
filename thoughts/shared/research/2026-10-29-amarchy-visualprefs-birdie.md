- 3.2 FIX: util/wb/VP-QuickFix 1.5n (30.5.2021), same author, "VisualPrefs - The Damage Control Edition", only the executables (VisualPrefs_000/020_030/040/060 + GUI_xxx), copy over 1.5k then reboot. https://aminet.net/package/util/wb/VP-QuickFix
  Fixes: 1.5k does not cope with Intuition V47; "all Workbench DrawInfo pens set to zero if started with no ENVARC:Sys/gui.prefs present" (wrong-colour bug, fixed in 1.5n); 3.2 support for ICONIFYIMAGE, frameiclass types, BARCONTOURPEN, honours IControl exceptions, titlebar height via system mechanism. New NOPALETTEPREFS switch (tooltype of GUI editor, brackets removed to enable) = GUI never reads/writes ENV(ARC):Sys/palette.prefs: use it if it conflicts with the 3.2 Palette editor. Author says: no further development, "use at own risk, it is a hack". Not tested by me on a 3.2.2/3.2.3 rig (UNVERIFIED beyond readme; a forum post reports a clean 3.2.3 + P96 + VP + FullPalette install with correct colours, itch.io thread via search, unverified).
- What it is: boot-time patch daemon (Run >NIL: C:VisualPrefs line in Startup-sequence IMMEDIATELY BEFORE C:IPrefs), patches Intuition/GadTools/frameiclass/sysiclass/OpenWindow, installs tbiclass, needs select.gadget. Reboot needed after install. Optional env: ENV:VisualPrefs/Special (bit flags), SafetyLevel, etc.
- Prefs file: ENV(ARC):Sys/gui.prefs, IFF "FORM PREF" with PRHD, GVER(4), then one "GUI " chunk (0x688 = 1672 bytes in the samples, binary, big endian shorts/longs; per-screen definitions + template). Verified by hexdump of themepack gui files. Internal layout of the GUI chunk is UNDOCUMENTED (guide has no struct); would need reverse engineering from samples (same size 0x6ae FORM in Crait/Mustafar). Also uses ENV:Sys/palette.prefs (system) unless NOPALETTEPREFS.
- Apply without reboot: the GUI editor "Use"/"Save" re-opens the Workbench screen (and other screens' GUI) at once, no reboot (guide, "Use"). No CLI/ARexx interface found in docs (grep: no ARexx). Unverified: whether VisualPrefs re-reads gui.prefs on a signal; the daemon is notified by the editor (semaphore, likely). Practical route for Amarchy: write gui.prefs + run the GUI editor? UNKNOWN headless; needs a test on a rig (tooltypes/CLI args exist: FONTNAME, SIZEBBOTTOM, NOPALETTEPREFS - check `GUI ?`).
- Pens: pen mode Absolute/Relative per pen; "All pens" per screen; colour locking page (locks colours later changed by programs; does not set value, so palette must already hold it at screen open). Since 1.5m the Absolute/Relative gadget is disabled for colours 0-3 and last 4 on Workbench (Intuition keeps those fixed).

## 2. FullPalette
- util/wb/FullPalette22 40.22 (9.5.99), same author, freeware-style (no fee mentioned). https://aminet.net/package/util/wb/FullPalette22
- FPPrefs (self-detaching) in Startup-sequence IMMEDIATELY AFTER IPrefs; reboot to activate. Edits all 256 WB colours; per colour Free/Locked (first 4 / last 4 always locked). Needs FPPrefs >= 40.20 for VP bitmap loading.
- Prefs file: ENV(ARC):Sys/fullpalette.prefs presumed (themepack ships name.fullpalette), IFF FORM PREF/PRHD/"FPAL" chunk 0xC08 = 8-byte header + 256 x 3 x 32-bit (R,G,B as 32-bit 0xRRRRRRRR, i.e. byte replicated) = 3072 bytes + header. Verified by hexdump (colour 0 = aaaaaaaa x3). Lock flags are in the 8-byte header region (UNVERIFIED; header bytes were 0 in sample, so lock map may sit elsewhere/after colours, need diff of two samples). Also still writes palette.prefs (8 colours) for compatibility; no longer depends on it. Env: FullPalette/Action IMMEDIATE|DEFERRED, FullPalette/ColorMode WORKBENCH|LINEAR, FullPalette/CopyColors TRUE. No ARexx/CLI documented. Apply: editor "Use" applies live; FPPrefs applies each time WB screen opens. Interaction with 3.2 palette.prefs: coexists with IPrefs; 3.2 Palette editor edits only 8 colours.

## 4. Colour specification
- VisualPrefs: DrawInfo pens map to PALETTE INDEX (pen number) with Absolute/Relative mode; not RGB. Actual RGB comes from the palette, so Amarchy must set the 256-colour palette (FullPalette FPAL, or at least WB 8 colours via palette.prefs) AND set gui.prefs pens to indices of those colours. Roles->indices: background/foreground/accent -> choose indices (e.g. 0..7 reserved for system; extra pens like active/inactive border light/dark, gadget fill need free indices >=8 and <n-4, lock them in FullPalette). FullPalette: RGB 32-bit per component.

## 10. Birdie (full treatment)
- Aminet util/wb/birdie2000 "Birdie 2000", Trond Werner Hansen (Tronan), 2005-10-21 upload, v2000 (1.apr.2000). https://aminet.net/package/util/wb/birdie2000 (homepage www.vgr.com/birdie, probably dead). Local: vp-dl/birdie/.
- What: a "hack" that redirects window-border rendering (Draw() in graphics.library, border bitmaps) to fill borders of PUBLIC screens with pattern pictures (datatypes) or generated gradients; on hi/truecolor also makes shine/shadow lighter/darker versions of the pattern. Optionally strips icon borders (NOICONBORDER). Docs say disable QuickDraw (MCP), Arq; give tasks more stack.
- Config: NO prefs file. Pure command-line args, run after IPrefs from Startup-sequence: `run <>NIL: c:birdie <options>`. Template: ACTIVEPATTERN/S,PATTERNS/M,NODRAW/S,NOBITMAPS/S,NOICONBORDER/S,NOLIGHTING/S,ACTIVECOLOR/K,IMPOSELEVEL/N,LRA/N,LGA/N,LBA/N,DRA/N,DGA/N,DBA/N,PRECISION/N,FLOODMASKMWB/S,PUBSCREENS/S,EXCLUDE/K,REDRAWLINE/S,REDRAWBITMAPS/S,MINDEPTH/N. Pattern entries are picture files (datatypes) or `gx.RRGGBB.RRGGBB` / `gd.R-G-B.R-G-B` gradients (high/true colour only). 1-20 patterns, random per window; ACTIVEPATTERN = first pattern for the active window, rest for inactive; ACTIVECOLOR=RRGGBB + IMPOSELEVEL% tints active windows.
- Live apply: none documented (no ARexx, no "Use", no signal). To change: kill the running Birdie (Break / `Status` + `Break`) and start again with new args; whether Birdie can be unloaded cleanly is UNVERIFIED (patch hack; likely stays resident, may need reboot). Risky for Amarchy live switching.
- Colours: RGB (8 bit per gun) in pattern pictures / gx/gd gradients / ACTIVECOLOR; NO pen numbers. On 8-bit (planar/CLUT) screens only the fill colour is changed ("In 8bit only the normal fill color is changed"), shine/shadow lighting is hi/truecolor only; PRECISION=32..-1 controls remap/pen allocation for AGA (it allocates pens -> exactly the "pens get reallocated" class of problem; FullPalette locking helps). So Birdie real gradients/pattern need a hi/true-colour RTG screen; on 8-colour/256-colour WB it is flat fill only.
- 3.2 compatibility: UNVERIFIED. No release since 2000; docs predate OS 3.2/V47 Intuition; no fix package found (Aminet search + web search: nothing). Birdie is still referenced by 3.2-era theme packs (old_OS_concept lists it), so it is used on 3.2 in practice, but I found no authoritative report. Needs rig test on 3.2.x (RTG/P96 screen and 8-bit screen).
- Licence: readme has none; Aminet "util/wb" = freely distributable by convention; no source, no explicit redistribution clause, author address (c2i.net) likely dead. Treat as: ship only with link/installer pointing at Aminet unless confirmed. UNCLEAR.
- Flat look with Birdie: single-colour pattern: `birdie gx.RRGGBB.RRGGBB` with start=end gives a flat theme-colour border fill (hi/truecolor); ACTIVEPATTERN with two such entries gives distinct active/inactive border colours; NOLIGHTING = old plain white/black bevel lines (not removed) so bevel stays; to remove shine/shadow bevel set LRA/LGA/LBA=0 and DRA/DGA/DBA=0 (no light/dark offset -> no visible bevel, theory from docs, UNVERIFIED); NOBITMAPS leaves system gadgets alone (let VP draw flat gadgets). No gradients wanted: avoid gx with different ends.

## 11. VisualPrefs + Birdie together (from VisualPrefs.guide, "Birdie" note)
- Both can run: VP "nearly 100% compatible" (tested with Birdie 1.5/2000) IF: per-screen option "Don't optimize border rendering" ON, Background pen = colour 0, and with Birdie NOBITMAPS set env `VisualPrefs/BirdieMode` = NOBITMAPS (must exist when VP starts; ENV(ARC):VisualPrefs/BirdieMode). Glyph pen is drawn as a darker shade of the border pattern on 15/16/24-bit unless Glyph pen = Shine pen (then lighter).
- Who wins: Birdie draws the border fill/gadget bitmaps (it patches below), VP defines geometry, frame styles and pens; on border fill Birdie wins when its optimisation switch conflicts; with NOBITMAPS VP owns gadget symbols. Startup order: VisualPrefs before IPrefs, FullPalette (FPPrefs) after IPrefs, Birdie after IPrefs (docs). Order between FPPrefs and Birdie not specified (UNVERIFIED; put FPPrefs first so the palette is stable before Birdie allocates pens).

## 12. gui.prefs settings for a FLAT look (VisualPrefs guide; field offsets still unmapped)
- System page: Frame = Borderless (or Filled) for system gadgets; Gadget style = Flat (or Future) symbols; custom bitmaps optional.
- Pens: set Shine/HalfShine and Shadow/HalfShadow (bevel pens) = same colour index as the fill (or as the Background pen) so bevels vanish; "Full 3D screen titlebar" off; "Text 3D disable"/3D disabled gadgets off; Special env bit 0x400 irrelevant (XEN only). Inactive-border fill/text colours configurable (distinct inactive look).
- GadTools/BOOPSI 3D frames: choose a flat/"Borderless"-type frame in the GadTools page (exact option names UNVERIFIED, need the editor on a rig; guide lists "exact look of BOOPSI and GadTools 3D frames").
- No gradients in VP; gradients are Birdie-only (hi/truecolor).
- Method to map file offsets: save gui.prefs with GUI editor, change ONE option, save again, binary-diff the 1672-byte GUI chunk (per option); repeat for frame style, symbol style, each pen, border thickness.
Sources: aminet.net/package/util/wb/birdie2000 (readme, Birdie.doc, FAQ, history local); VisualPrefs.guide Birdie section (local); web search found no 3.2 info for Birdie.
